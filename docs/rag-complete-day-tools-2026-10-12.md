# 避免重复读取已完整提供的日志

## 原因和修改

上一轮排错材料初次检索已返回两篇短日志的完整正文，Agent 仍请求读这两天。既有片段 truncated 标志不能证明当天其他小节也已提供；按是否截断一刀切地关掉 read 会漏掉同一天未命中的小节。

MCP 搜索新增可选 dayFullyProvided，逐节比较当前返回片段与解析后的原文，包括前言和空标题；缺节、截断及不能精确复原的合并片段均不算完整。该标志与 dayContentHash 一起校验。证据集合只在提供的正文未被压缩、哈希不变且没有截断时排除当天补读；旧服务未提供标志时保持可读。此前按已执行范围禁重复读取的规则继续保留。Agent SDK 可用工具和执行校验共用证据集合的可读日期。

不增加模型调用或新判断器，不改变查询日期范围、来源编号、SSE 或会话格式。完整提供某一天不证明全库已读完，也不证明证据支持问题。

## 验证和边界

- 155 项 RAG 测试通过。覆盖完整短日、缺少前言/小节、空标题、截断、压缩后的哈希变化、旧服务兼容、非法元数据和已尝试日期。源码修改期间出现过一个测试失败：旧版本冲突用例已提供整天，故 read 被正确关闭；改用确有未命中小节的同日材料后，仍证明读取期间修改来源会停止答案，不削弱版本保护。
- MCP 全套 51 项：50 通过、1 项既有跳过，另跑协议冒烟 10/10；生产构建含类型检查通过。实际生产路由及 Chromium/WebKit 浅深色验证使用合成资料和模型，七组检查完整日不提供 read、一次调用完成回答、引用及会话保存。证据 `.local/rag-entry-production-1791736830457/results.json`；已实际查看 Chromium 浅色与 WebKit 深色截图。
- 原固定完整语料重新取证（不调用模型）：排错记录 2026-08-04 与重连说明 2026-08-12 均完整提供并排除补读。另篇 2026-09-01 长归档记录确有截断，仍保留补读资格；读书材料两天均完整提供，可读日期为空。证据 `.local/rag-day-complete-corpus.json`，原合成资料未修改。

这些证据证明此前两次重复读不能再执行，不证明排错问题下一步必然直接回答：模型仍可能搜索、选择别篇截断材料或只返回 finish reason。没有追加付费试验，默认启用门槛仍待跨材料重复对照及 Windows 打包启动检查。仅本地提交，不推送、发布或安装，个人版及真实记录未操作。
