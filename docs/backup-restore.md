# 离线整实例备份与恢复

整实例归档用于同版本灾难恢复和搬迁，保留实例身份及凭据。它与页面中的内容导出、单日日块回退不同：内容导出不是实例备份，日块回退也不会恢复配置、模板或问答会话。

Windows 本地包可直接在启动页使用“备份与恢复”，无需另装 Node；入口会先停止自己管理的服务，成功恢复后选中新目录，操作见[Windows 本机使用](windows-portable.md#备份和恢复)。源码或 Docker 用户使用下文命令。两种入口使用相同归档格式与新目录恢复规则，均应先关闭外部资料编辑器。

## 归档范围

| 路径 | 处理 |
| --- | --- |
| 实例根 `.env` | 必需，逐字节保存，包括访问密码、会话密钥及已配置的服务凭据 |
| 实例根 `.env.mcp` | 可选，存在时逐字节保存 MCP 独立服务配置与凭据 |
| `data/` 全部内容 | 包含 `.instance.json`、月/年 Markdown、随记、附件、写作／标注／提取模板、个人生成方案及默认选择、收藏、分类、问答会话及恢复标记；不转换原文件组织或换行 |
| `backups/` 全部内容 | 保留写前版本；随记未完成事务的标记可能引用这些文件，因此一并保存 |
| `data/.instance-operation.lock` | 仅当前备份持有的锁不进入归档；不会接管或清理其他操作遗留的锁 |
| `index/` | 派生索引不归档；恢复后创建空目录，按部署配置重建 |
| 实例根其他文件 | 不归档，包括截图、报告、构建输出和用户另放的文件 |

归档包含私密资料和真实凭据，**不是可公开分享的导出文件**。命令不会打印环境配置内容。归档本身不加密；请在受控位置保存归档与摘要，离机保存时使用自己的加密存储方式。

## 备份与核验

需要 Node.js 22.13 或更新版本；工具仅使用 Node 内置模块，不需要安装 Web 依赖。先停止该实例的 Web、MCP 及外部编辑器。正式启动入口与本工具使用同一实例锁，在线 Web 或遗留锁会使备份失败，见[维护锁说明](maintenance.md)。直接绕过启动器的进程和外部文件编辑不受这把锁保护。

所有参数都必须是绝对路径。输出父目录须已存在，归档必须放在实例目录之外。归档与其摘要文件都不得已存在；推荐每次使用新文件名。

```powershell
node ops/archive-cli.mjs backup "D:\workbench-instance" "E:\private-backups\workbench-2026-09-22.slwb"
node ops/archive-cli.mjs verify "E:\private-backups\workbench-2026-09-22.slwb"
```

```sh
node ops/archive-cli.mjs backup /srv/workbench-instance /srv/private-backups/workbench-2026-09-22.slwb
node ops/archive-cli.mjs verify /srv/private-backups/workbench-2026-09-22.slwb
```

成功会得到 `.slwb` 文件和同名 `.slwb.sha256` 文件。扩展名只是约定，两份文件必须一起保留；改归档名时需同步改摘要文件名。摘要文件内容只有整包 SHA-256。核验还会检查归档内部每个文件的大小和 SHA-256，以及实例身份与必需凭据。SHA-256 用于发现损坏，不能证明归档来自可信作者；它不提供签名或加密。

备份先写独占 `.partial` 文件并完成核验，再以不覆盖既有文件的方式发布摘要和归档。两份文件的发布不是一个文件系统事务。失败可能留下 `.partial`、其摘要，或只有正式摘要而没有归档；这些均不是已完成的备份。保留现场检查，不要手工把它们改名冒充成功。下一次使用全新归档文件名；本工具不删除旧归档、备份或失败现场。成功路径只移除本次发布后的临时名称。

## 恢复到新实例

选择**尚不存在**的目标目录，其父目录须存在。空目录也不允许作为目标。恢复不会覆盖、导入合并或修补已有实例，也不重新生成身份和密码。

```powershell
node ops/archive-cli.mjs restore "E:\private-backups\workbench-2026-09-22.slwb" "D:\workbench-restored"
```

```sh
node ops/archive-cli.mjs restore /srv/private-backups/workbench-2026-09-22.slwb /srv/workbench-restored
```

命令先完整验证归档及摘要，然后独占创建目标目录，在新 `data/` 内持恢复锁，逐项写入并再次验证内容。成功才释放锁。恢复后使用匹配版本代码启动新路径，不需要先运行初始化；源实例和原归档不变。

身份、访问密码、会话密钥及原配置全部保持原字节。因此，在凭据未变且尚未过期的前提下，原有认证令牌仍使用相同身份与签名密钥；网页 Cookie 能否继续发送还取决于浏览器域名、路径和 Secure 设置。恢复不会延长令牌期限。服务端地址、MCP 地址、代理设置和外部供应商凭据也原样保留，迁到另一台机器时应自行核对这些配置；工具不会连接外部服务或验证其可用性。

如果源资料含随记 `.pending-write.json` 等恢复标记，归档会忠实保留它及备份，不把未完成事务伪装成正常状态。恢复后仍须按[随记恢复流程](notes-storage.md)核对，不能仅因归档校验通过就清除标记。

恢复期间写入失败会留下新目标、`.restore-incomplete.json` 和已建立的 `data/.instance-operation.lock`，供检查磁盘、权限及部分写入结果。很早的目录或标记创建失败可能尚未建立数据锁，目录仍会保留。**不要启动失败目标，也不要继续向它恢复。**保留现场，在故障解决后选择另一个不存在的新目录重试。已有目标以及并发恢复都会被拒绝；无自动删目录或自动解锁命令。

## 格式、限制与权限

当前格式为 `study-log-instance` 版本 1：固定标识、有界 JSON 清单、按清单顺序排列的原始文件字节。不使用 tar/ZIP、不压缩，也不会调用通用解压器。清单记录相对路径、文件类型、大小和逐文件摘要。目录按相对结构恢复，包含空目录。

- 归档总大小（含清单）最多 **20 GiB**；最多 **100000 项**文件和目录；清单最多 **16 MiB**。
- 根 `.env`、可选 `.env.mcp` 和身份文件各最多 **64 KiB**。文件内容采用 **64 KiB** 缓冲流式处理；清单和路径表仍按上述上限驻留内存。
- 路径最多 32 层、UTF-8 总长 1024 字节、单段 255 字节。只接受正常相对路径，拒绝越界、反斜杠、盘符/ADS、Windows 保留名称、尾部空格/句点、短文件名别名模式、非 NFC Unicode 名称及忽略大小写后的重名。
- 实例、归档及目标路径上的符号链接、Windows 目录联接均拒绝；被归档的文件以及归档/摘要文件不能是硬链接或特殊文件。不会跟随链接去读写另一实例。
- 工具所在文件系统需支持普通文件、独占创建和硬链接发布；NTFS/Linux 本地文件系统已用于合成测试。不要把同步盘或网络文件系统的并发、断电行为当作已验证事务保证。
- 命令行工具的新文件权限请求 `0600`，目录 `0700`；Windows 仍受 NTFS ACL 控制。Windows 本地包额外在写入归档内容前设置文件私有 ACL，并在向恢复目录写入内容前设置目录私有 ACL，权限设置失败即停止。不保存原 UID/GID、ACL、文件时间或执行位，不自动调整所有权。Docker 恢复应使用与目标服务一致的容器用户/卷权限；不要把普通宿主用户恢复出的目录直接交给另一 UID 后假定可写。

该格式只承诺当前版本自己的读写和同版本恢复；它不是旧候选 tar/ZIP 归档的兼容读取器，也不代表跨版本升级/降级已验证。
