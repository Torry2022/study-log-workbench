# 同一步工具调用不能重新打开结束状态

实际 SDK 与 MCP 的合成检查复现了一个缺陷：同一步包含搜索和 `finish`，搜索先发出、结束工具先返回时，搜索结果会覆盖停止状态，继续发起下一步模型调用。

搜索及读取完成后现在只允许进入停止状态，不能清除已有停止状态。已经发出的只读请求仍可完成并登记证据；先执行结束时，后面的工具按已有保护跳过。没有增加阶段、工具、轮数或预算。

专项分别检查搜索→结束、结束→搜索两种顺序，修复前出现两次模型决策，修复后两种排列均只有一次。独立最终回答及内部消息隔离沿用原逻辑。

类型检查和生产构建通过。机器 Node 23 的并行全套中，摘要专项出现一次未收到请求的失败；该专项独立运行通过，未修改其断言。使用部署候选的 Node 22.23.3 串行执行完整 168 项 RAG 检查通过；前述并行失败原因尚未确定，不能据此宣称并行运行已稳定。当前生产接口和 Chromium/WebKit 浅深色九项检查通过，已查看截图，证据在 `.local/rag-entry-production-1791789009033/`。

本次验证仅使用合成材料及模型替身，未新增付费模型调用。质量门槛继续，默认 Agent/Jev 关闭；既有 Windows 候选尚未包含本次修改，未推送、发布或安装，鸿蒙未改。
