# 首轮证据足够时合并回答

## 改动

实验 Agent 使用主回答模型取证，避免把轻量模型的输出直接作为最终答案。首轮证据足够时，`finish` 可携带最多 4000 字符的回答；已有补查、没有证据、参数错误或流未完整结束时，不允许通过这个入口交付答案。旧的仅返回 reason 的 finish 仍兼容，继续单独生成最终答案。

两种回答模式、历史、覆盖信息沿用 buildRagMessages；回答经过现有来源编号、引用和输出规范化，不将工具消息或内部文字写入会话。首轮答案在工具参数和结束原因检查后一次发送 delta，因此不会逐字显示。复杂问题仍补查后单独生成回答；没有增加判断模型或工具预算。实验开关仍默认关闭。

## 本地验证

- 最终 RAG 测试 153/153，类型检查和生产构建通过。新增测试覆盖两种回答模式、主模型选择、一次调用、补查后禁止直接回答，以及输出长度中断不交付部分答案。同一步同时发起 search 与 finish 时，也不能把补查前的答案直接交付。
- 实际生产路由、真实 MCP、合成模型：普通事实、字面查询、整月总结共三组均一次生成调用；Chromium / WebKit 浅深色四组实际页面提问、引用和会话保存通过。合成日志未改变。
- 证据：首次运行 `.local/rag-entry-production-1791736193299/results.json`，并行工具保护后的最终构建复跑 `.local/rag-entry-production-1791736424639/results.json`，两次均七组通过。首次实际查看 Chromium 浅色和 WebKit 深色截图，最终构建另查看 WebKit 深色截图，回答、来源及会话均正常。

| 排错记录，第 2 次 | 请求被预算代理拦截 | 未执行 | 不计质量通过、不计模型失败 |

证据：`.local/rag-finish-answer-1791735888361/`。共 7 次实际上游调用，按已报告 usage 的保守费用上限 0.11745 元，未结算预留为 0；不是供应商账单。拦截原因是下一请求的最坏情况预留超出剩余额度，随后停止，没有自动追加付费重试。更早以 0.12 元单组额度启动的运行在首请求前被拦截，实际上游调用为 0，之后改为原有 0.38 元总额度共享分配；未扩大已授权预算。两组原资料哈希均未改变。

本轮证明首轮直接回答能减少部分简单查询的一次额外调用，不证明跨材料复杂问题收益稳定，也不满足默认启用门槛。后续仍需解决无新增证据的多余读取、固定复杂材料重复收益及 Windows 打包启动检查。仅本地提交，未推送、发布或安装。
