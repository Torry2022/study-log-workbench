# 鸿蒙公开版迁移记录

鸿蒙客户端与 Web/API 保持同一仓库，连接使用者明确配置的自部署实例。网页及支撑服务已有维护者合成验收，独立使用者试装尚未完成；这不再阻止客户端开发，但仍是公开发布前的未完成门槛。客户端自身的独立安装与跨端验收也须另行取得证据。

当前目标是 GitHub 源码及可验证的侧载路径，不以应用市场上架作为本阶段的完成条件。签名材料、用户资料、个人服务器地址和真实实例配置不得进入源码或安装包。

每个批次按可独立验证的用户结果拆提交。迁移时核对资源加载、入口连接、状态归属、生命周期和设备上的真实操作；文件存在或构建通过不等于功能通过。界面依据 `DESIGN.md` 与既有产品交互复核，改变行为时记录原因和前后差异。发现可复现的原架构缺陷，另记影响与复现方法，再决定是否需要局部重构。

不迁入个人 Wiki 编译、专用写作风格、个人服务默认值、App Linking、碰一碰、跨设备接续和完整离线同步。通用的导入导出、备份、AI 与问答只使用公开服务契约，客户端不保存模型密钥。未配置模型时基础读写仍须可用。

验收只使用独立合成资料；每项记录当前提交、构建、测试数据、设备及实际结果。没有执行的设备、签名安装或独立试装不能标为通过。

## H0 验证记录（2026-09-24）

个人版鸿蒙源码与既有迁移清单使用的来源基线一致；旧公开候选含未提交修改，仅作参考，未作为新仓输入。服务端核对了 App 登录、能力接口、日志空实例读取及问答入口，修正了契约文档中“AI/问答尚未实现”的过期表述。

`node ops/harmony-contract-smoke.mjs` 在两个新建的本机合成实例通过：两个实例身份不同，五项可选能力均报告已支持但未配置，各自 App Token 可读取本实例、不能访问另一实例，空实例的月份接口可读取。原有 `auth-smoke.mjs` 也分别通过错误密码、Cookie、App Token、过期令牌及注销检查。此结果只证明当前服务协议，不代表客户端连接已实现或真机通过。

## H1 工程验证记录（2026-09-24）

在 `study-log-harmony/` 建立公开包名 `org.studylog.workbench.publicedition` 的独立工程，目标设备为 phone、tablet、2in1。当前清单只有 `INTERNET` 权限，未声明个人域名、App Linking、接续或系统文件分享入口；分享会在材料导入真正接通后另行验收。图标沿用公开版资源，签名配置为空，本机 SDK 路径由不入库的 `local.properties` 提供。

本机 DevEco/Hvigor `assembleHap --no-daemon` 成功，生成 `entry-default-unsigned.hap`，SHA-256 为 `FA52AAC74D330D5EA2D76DB9BCBCF0E15CECCB33E0DCCDC0909A214D8866AACA`。已检查构建产物和本机 SDK 配置均被忽略，源码未命中个人域名、分布式权限或签名材料。构建有 `loadContent` 可能抛异常的 ArkTS 提示及“无签名配置”提示；后者符合当前无签名阶段。页面仅说明迁移状态，不能当作登录、导航或设备体验已完成。

## H2 当前进展

已迁入公开实例地址规范化、固定 API 前缀、实例切换代次和完整五项能力字段校验。原生请求层目前只提供登录与能力读取所需的 GET/POST，禁止自动重定向；实例或令牌更换后，迟到的 401 不会清理新会话。实例设置按 origin 与服务端身份分配本地命名空间，Token 写入设备本地 AssetStore，不跨实例共用。

`npm run test:protocol` 六项测试通过，覆盖地址、能力、路径、旧请求、A→B→A 命名空间及延迟令牌写入；无签名 HAP 仍能编译。纯逻辑测试不证明客户端连接成功。

成熟登录页的布局、纹理、字体选择与键盘处理已作为公开版连接入口迁入，另加服务器地址与显式本地 HTTP 测试选择。入口接通 App 登录→能力探测→实例命名空间→设备本地 Token 保存，也尝试恢复已保存连接；无签名 HAP 编译通过。连接成功后暂显示迁移状态页，业务模块尚未开放。当前没有设备操作证据，连接、恢复和切换均保持待设备验收，不能把协议测试当作真机通过。

## H3 当前进展

已按既有客户端的字体族注册方式接入系统中文衬线字与随包的日期、拉丁衬线和等宽字资源。无签名 HAP 编译通过，并逐项检查五份字体文件及其 OFL 文本都进入产物。连接页同时接入与系统浅深色同步的资源色。字体文件存在、注册代码可达及深色资源打包仍不足以证明各设备真实字形、尺寸和回退效果；这一部分与导航一并留待设备逐屏核对。
