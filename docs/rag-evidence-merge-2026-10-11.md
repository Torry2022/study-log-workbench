# 小节与完整日块的重复证据（2026-10-11）

## 修正

此前短排错题命中两个小节后，Agent 又读了两个完整日块；不同的 chunkId/hash 使同一正文保留两次，并在回答中重复引用。本批在请求内证据集合增加精确覆盖检查，不改变 MCP、SSE 或客户端字段。

- 完整日块必须无截断、从偏移 0 开始，且原文 SHA-256 与返回的整日 hash 相符，才解析其前言与三级小节。复用已有 Markdown 根标题解析，代码、引用或列表中的标题不参与分节。
- 只有日块的每段正文都已被同文件、日期、小节序号、标题及正文 hash 的完整搜索结果覆盖，才不重复加入日块。省略的来源仍保留原编号、标题定位和 hash；完整读取覆盖状态独立保留。
- 先读完整日块再搜索时，按原文计算并缓存小节指纹；后续摘要改变提示正文，不改变原文指纹。只有完整日块来源仍实际保留时，才用它省去重复小节。
- 新前言、新正文、重复标题的不同小节序号、标题变化及空标题段落不能按“相似”丢弃。分页或截断不能证明整日被覆盖。出现真正新增上下文时保留整日原文，不剔除其中的重叠段落。

仍保留现有同 chunkId 版本变化拒绝、证据字符/数量预算和来源编号规则。没有把多版本 hash 变成通配符，也没有改写原始资料。

## 验证

142 项问答检查通过，新增用实际 MCP 解析、检索及范围读取构成的四组回归：两种读取顺序、摘要后的原文身份、额外前言与正文、重复标题、围栏代码伪标题、分页末尾、版本变化、空标题段落；清除实际来源后也不能仅凭缓存宣称已有证据。原 SDK 集成测试此前期待两个重复来源，现改为保留一个原小节并以 no_new_evidence 停止。

同样的排错、读书材料及问题、最终模型，Agent 路径各重复两次：四次均保留两条正确日期来源，不再重复引用同日小节/日块；条件、否定、无需重连额外批准、读书方法适用限制均保留。排错两次从三次模型请求降到两次，耗时 2.651 / 1.747 秒；读书仍两次请求，耗时 2.348 / 1.882 秒。四次均以 no_new_evidence 结束，说明去重阻止继续累积重复片段，不证明理解问题的语义判断已可靠。

第一次排错回答附带了原文未记录后续实际重连的缺口说明，且措辞较冗余。补查仍比已够用的普通 RAG 多一次模型请求。因此 Agent/Jev 继续默认关闭，不用本次去重收益代替默认启用质量门槛。

八次供应商请求均完成，按返回用量估算费用上限 0.019968 元，非实际账单；没有 Jev 请求或重试，合成源 hash 不变。证据：`.local/rag-evidence-merge-evaluation-20261011/report.json` 和 `ledger.jsonl`。类型检查和最终生产构建通过；独立服务包 Node 22/Web/MCP、认证 SSE、自定义完整 URL、SDK 循环及 Chromium 宽窄问答流程检查通过，包括连续提问、后台标题、历史、来源往返、停止/中断和保存重试。包与证据：`.local/rag-evidence-merge-payload-20261011`、`.local/rag-evidence-merge-package-check-20261011`。

## 保留边界

本批解决的是完整日块与已覆盖小节的精确重复。只有部分重叠的长分页材料继续全部保留，避免删除真正新增上下文；因此未宣称所有长材料重叠都已消除。不同 chunkId 的跨时间修改仍不能仅凭不相等的正文 hash 判断是新增上下文还是源修改；现有分页 revision 和同 chunkId 保护继续生效，跨方式整日版本绑定另需明确共同身份后实现。

没有引入新的判断模型或扩大工具权限。网页、Windows、鸿蒙复用同一后端；本批没有鸿蒙设备现场操作、发布或安装。
