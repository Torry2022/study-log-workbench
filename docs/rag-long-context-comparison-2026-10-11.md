# 长材料与沿线索补查对照

## 本批修正

隔离合成样本发现实际分页缺陷：首次相关性搜索截断时，`run.limited` 已为 true，随后读取完整日块的循环也据此停止，未继续读取文末。现在分页只在达到证据容量上限时停止；工具次数、重复请求、取消和版本检查仍由现有机制执行。138 项问答测试通过，包括实际 MCP 分页、SDK 两步读取/换词搜索、分批整理及最终来源引用的完整数据流。

真实样本另发现原补查提示会重复读取或过早结束。补查规则明确：截断且缺少依据时读取原文，发现另篇记录或规则名称时搜索其内容；已执行的读取不重复，仅知道规则名称不足以回答具体条件。没有增加模型、工具或执行层，Agent/Jev 仍保持实验关闭。

## 固定材料与方法

`scripts/rag-long-context-corpus.mjs` 生成 45294 字符的合成材料，包含两个日期：长篇归档预览采样，以及另篇保存规则。首轮搜索只命中前文；文末指向另一篇规则，规则明确无新增字段、来源路径一致、用户明确确认三项条件及 AI 不得自动保存。使用实际 MCP 服务；测试前确认首次检索不含规则名称，完整分页能读到它，按名称搜索能取得规则正文。

这超过项目 30000 字符单批预算，不是超过供应商原生上下文窗口；DeepSeek 当前模型原生窗口为 1M。材料以采样 JSON 为主，不能代表所有长中文文章。最终回答与取证均使用 `deepseek-flash`，测试统一关闭 thinking，保留各阶段输出上限；每题每路重复两次。

两类问题分别检查：

- 未指定日期，只有一条命中线索：是否读到文末，再查到另篇记录并引用具体条件。
- 明确比较两个日期：先完整读取范围并分批整理，再比较普通 RAG 与 Agent 的额外补查是否有收益。

## 实际结果

| 场景 | 普通 RAG | Agent | 结论 |
| --- | --- | --- | --- |
| 沿线索补查，原提示 | 两次均说明材料不足，未编造完整条件 | 两次均未查到规则正文；一次读到规则名但重复读取，另一次搜索无新增材料后停止 | 原路径未完成任务 |
| 沿线索补查，修正提示 | 两次均说明材料不足；各 1 次模型调用，约 1.3 秒 | 两次均找到另日规则，回答三项条件、否定和不得自动保存，并引用该规则；各 6 次调用，5.0/6.5 秒 | 该固定样本显示重复收益，不代表全面质量通过 |
| 明确日期范围 | 两次都提供三项条件和禁止自动保存；各 3 次调用，4.5/4.7 秒 | 一次直接结束取证，4 次调用、5.7 秒；另一次预留上限拒绝摘要，回退截断，不能作为同条件对照 | 完整范围不需要额外补查来获得这些条件 |
| 日期范围的受控复查 | 沿用上述已完成结果 | 检查预留拒绝后仅重做原 Agent 项，4 次调用、6.3 秒；条件正确，但补查引入重复片段和部分读取标记 | 没有观察到内容收益，反而增加来源与范围噪声 |

这里只核对条件、否定及相应来源。模型对“当天为何未完成审批”的推断仍需谨慎：没有确认记录不能证明具体哪一项条件不满足，不把答案措辞流畅视为因果结论可靠。
