# 取证工具选择改进

## 实现

取证输入补充 `availableReadDates`：仅列出已有证据中命中的日期，排除本轮已经发起范围读取覆盖的日期。它表示可发起的新读取，不是已读全的证明；完整/失败/部分读取仍看原覆盖记录。

工具说明明确区分读取命中片段和搜索尚未找到的规则：缺少所问依据且命中片段被截断时，优先读对应日期，再按原文的具体名称查找。没有可读日期时，通过 SDK 的 `activeTools` 不再向模型提供 read；执行层也校验可读日期。没有增加路由或判断模型，仍是两轮决策、八次 MCP 调用和共享取消。已有充分证据时仍可 finish；不能据此证明初次检索穷尽。

## 对照证据

沿用原合成语料及普通措辞“北辰归档流程可以直接保存吗？请给出最终保存条件。”，不隐藏规则，基础路径与 Agent 最终模型同为 deepseek-flash、reasoningEffort=none。未调用 Jev。

1. 可读日期和读取优先级改动后，两轮 Agent 都读取了原文；一次继续查到 9 月 18 日规则并保留三个保存条件和否定，另一次重复已执行请求而停止，未取得具体规则。基础路径两次缺少具体条件。报告 `.local/rag-tool-choice-1791734934579/`，14 次上游调用，折算用量上界 0.357165 元。
2. 增加工具资格限制后，单轮 Agent 查到规则，保留来源一致、没有新增字段、用户确认及 AI 不能自动保存等限制，耗时 4627ms、六次模型调用；基础路径仍说明缺少规则，1145ms、一次调用。报告 `.local/rag-read-availability-1791735098820/`，七次上游调用，折算用量上界 0.17938 元。

两批均无代理拒绝、无未结算预留，来源文件哈希不变。上述金额为保守用量核算，不是供应商账单；仍使用前轮 1.4 元验收上界内的余量，没有为失败自动开启付费重试。第一批一成一败、最终改动仅一次成功，不足以证明不同措辞/不同材料的稳定收益；step_limit 也不等于全库取证完成。
