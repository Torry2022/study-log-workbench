# 整体适用性核查与默认体验（2026-10-08）

## 结论与范围

本轮覆盖现有模块的源码核查与下列有限流程，修复已确认的问题；不把“功能已实现”当作“全部使用体验已验证”。产品仍面向愿意使用 Markdown 的技术学习者，基础标注、提取、分类和问答不额外限定学科。中文、单使用者、Asia/Shanghai、月／年文件及现有标题语义保留。

本轮没有新增设置、标注模板选择器、学科预设或端侧业务实现。沿用原组件、字体、颜色和布局，只修改标注说明。所有写入和模型请求均在隔离合成实例；本机替身能验证协议、来源和事务，不能证明真实模型质量，也不是真实用户反馈。

## 已确认问题及修复

1. **标注说明偏技术，与已有通用模板不一致。** 网页与鸿蒙同步说明为“挑出值得回顾的概念、结论和必要条件，以加粗标记重点，保留原文。”移除“日块”这一内部称谓；不重画界面。
2. **问答提示词无必要地限定技术内容。** 上下文改写、检索规划和回答补充知识用词已中性化；不改变返回结构、来源编号、知识补充模式或拒绝执行材料内指令的约束。
3. **已有默认模板不会随源码修正到达旧实例。** 新增精确摘要升级，详见下一节；未采用关键字或相似度猜测。
4. **鸿蒙启动阶段直接注册窗口监听可能抛出 1300002。** 已改为内容就绪后注册并保护窗口销毁及前台重试。实际故障证据、源码测试与模拟器范围见[窗口生命周期记录](harmony-window-lifecycle-2026-10-08.md)。
5. **历史版本浏览器测试使用旧名称。** 修正定位器并重跑原断言；这是测试维护问题，不冒充产品修复。首次失败日志保留。

## 默认模板升级的安全边界

只登记 rc.5 标注模板的 LF／CRLF 精确摘要。`ops/instance.mjs` 被初始化工具、Web 服务监督器、Windows DesktopManager 共用；先取得实例锁，再维护模板，再启动服务子进程。备份写入和 fsync、备份一致性、源文件二次检查完成后原子替换。链接、非普通文件、超限、读取不安全、未知内容一律不覆盖。

旧文件备份及更新／跳过／失败记录在 `data/prompts/.default-upgrades`。重复启动不产生重复备份，也不重写当前模板。备份或替换失败保留旧文件；真实服务入口故障测试仍可启动并执行合成基础写入。generation.md、extraction.md、个人方案、默认选择和凭据均不修改。新实例直接使用当前内置模板。

Windows payload 与 web/tools 镜像原有构建清单已包括 `ops/instance.mjs` 与 prompts，启动链路加入调用后无需另设升级器；本轮验证包内对应文件逐字节匹配当前源码。已发布 rc.5 未改变，不会因为维护者更新源码就自动获得这份修正。

## 不改动的约束与下一轮候选

- **保留**技术学习定位、三套生成预设、单使用者与现有文件／日期／标题协议；不扩大学科定位，不添加更多配置来代替默认行为。
- **体验假设，后续优先观察**：无标题短记录与 H3 小节统计的理解差异；标题搜索与全文搜索的可发现性。当前未有真实用户证据，不新增统计口径或自动结构化。
- **质量待验**：四类合成材料的真实模型少量标注／提取／回答。无法可靠确认剩余授权费用，因此本轮不调用付费服务；替身通过不能换成“质量已通过”。
- **既有交付条件待验**：外部受信 HTTPS 多端连接、独立鸿蒙签名安装及明确版本组合的升级保留。新增模板迁移验证不等于完成所有跨版本升级。
- **后续候选准备**：本轮源码、测试、文档完成本地收口后统一选下一候选版本；发布前重建并核对最终安装器和镜像。本轮不推送、不更换 rc.5 标签／附件、不覆盖日常应用。
