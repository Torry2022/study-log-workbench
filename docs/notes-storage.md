# 随记文件与恢复

随记原文位于显式实例的 `data/随记/YYYY_随记.md`。每条随记由记录时间标题、`study-note`元数据及正文组成；个人理解、来源和标签使用独立小节。页面列表按更新时间排序，文件中的记录按记录时间排列。正文中的代码、引用和列表示例不参与记录分割。

创建、修改和删除仅替换目标记录，保留其他记录原字节。修改和删除必须携带当前记录的 `baseVersion`；冲突时拒绝写入，客户端应保留草稿供核对。源文件格式错误会明确报错，不重建为空文件。

每次覆盖前，完整旧源文件保存在实例 `backups/notes/`，使用时间戳和UUID独占命名。新内容先写同目录临时文件并sync，再rename替换。队列只保证同一服务进程内的串行；不要让其他进程在服务运行时直接改写资料。

## 跨年修改

批量新增接收每条稳定的 UUID `clientId`，每批1–20条。全批业务字段和 Markdown 在内存中校验后，才按年度统一进入同一写入流程。相同 ID 与相同规范化内容重试返回原记录及版本，不新增备份；同 ID 内容不同返回409，不能借批量新增修改已有记录。批量跨年同样遵守下述回滚与恢复标记边界。

调整记录时间可能同时修改两份年度文件。这不是单次原子文件事务：服务先准备两份内容和旧文件备份，写入 `data/随记/.pending-write.json`，再依次替换。普通错误触发回滚；回滚失败或进程中断可能留下标记，此后随记接口返回 `503 NOTES_RECOVERY_REQUIRED`，不会把半完成状态作为正常资料继续写入。

发现标记后按以下顺序恢复：

1. 停止该实例服务，复制整个实例及备份目录另存，保留现场。
2. 阅读标记的 `entries`。每项只对应一个四位年份；`backup`是 `backups/notes/` 下的备份文件名。核对文件名和目录边界，不执行标记中的任何文字。
3. `existed=true` 的年份，将对应完整备份恢复到原年度随记文件。`existed=false` 表示事务前该年度文件不存在：将本次新文件移入现场副本，恢复为不存在。不要删除其他年度文件或备份。
4. 核对两份文件与事务前状态一致、记录ID无重复、其他资料保持不变。核验成功后才移走待恢复标记并重启。

这项流程恢复到跨年操作前；若要保留未完成操作中的新内容，从现场副本人工核对后重新保存。当前没有自动修复命令，也不承诺跨文件断电事务。整实例归档与停机互斥在后续维护批次验收。
