# Windows 重启后再次打开修复

## 问题及处理

rc.8 发布后发现：Windows 重启会留下旧桌面服务的运行记录，程序在再次打开时仅根据目录存在就拒绝启动。此前人工留存记录并重新打开只恢复了当次使用，没有解决源码问题。

本次修正：

- Electron 接入 Windows `query-session-end` 和 `session-end`。前者走既有关闭流程，用户取消时保留草稿和服务；后者启动服务收尾。连续事件不会再次写入同一份偏好设置，结束过程中不重新打开窗口。
- 桌面服务运行记录包含本机／当前账户摘要、系统启动周期、规范化保存路径、数据身份、父子进程号及创建时间。子进程先登记再启动，父进程断开时请求子服务结束。
- 再次打开时，仅对归属匹配且确认没有原服务、没有未完成写入的本机固定磁盘记录自动恢复。Windows 独占文件句柄协调并发恢复；旧记录移到 `.desktop-recovery/`，正文和配置不改写。
- 仍在运行的父进程／子服务、随记待恢复标记、临时写入、外来或移动后的记录、旧版缺少身份信息的记录继续保留，不能猜测安全。服务器和维护操作不扩大自动恢复范围。

## 验证

- `ops/desktop/recovery.test.mjs`：6 项通过，覆盖重新打开、前次启动周期及 PID 复用、子服务仍在收尾、未完成写入、外来／旧记录、并发恢复。证据 `.local/desktop-recovery-tests-final.log`。
- `ops/desktop/desktop.test.mjs` 与 `ops/service.test.mjs`：19 项通过，1 项仅适用于 POSIX 信号的检查在 Windows 按原规则跳过。覆盖在途写入、正常退出、异常子服务、端口占用、归档恢复、目录只读检查和锁归属。证据 `.local/desktop-restart-regression.log`。
- 独立 Playwright 驱动最终打包 EXE，6 项通过：取消退出保留草稿、确认退出及重开、会话结束收尾、注入前次启动记录后自动打开、实际终止隔离主进程后自动重开、关机查询和会话结束连续到达。首次故障脚本误终止 Playwright 的 Windows 包装进程，随后改为核对运行记录中的实际 Electron PID 再注入故障，完整重跑通过。证据 `.local/desktop-restart-1791527964032/report.json`。

系统会话事件和前次启动周期使用受控注入；没有重启维护者电脑，不将这些结果写成实际系统重启已验收。实际主进程终止使用全新合成保存位置，没有操作日常记录。

仅本地修复与打包验证；未推送、替换已发布 rc.8 或覆盖日常应用。验证包位于 `.local/restart-fix-20261009/`，其中版本号沿用源码 rc.8，仅用于本地检查，不是公开 rc.8 附件。
