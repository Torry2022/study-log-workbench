# 工作台界面一致性复核

本轮试用发现：此前的流程回归可以证明保存、恢复等操作成功，却不足以证明界面迁移完整。界面一致性需要另行核对组件结构、原样式、响应式收纳和实际截图，不能从服务测试通过推导。

## 修复范围

- 日志文件名恢复12px、次要文字颜色及省略规则；日期字体保持既有资源。
- 日志工具栏恢复日期导航、次操作、模式切换、刷新、导出、备份、删除、更多、保存的结构与顺序。按阅读区宽度切换图标并逐级收纳；手机操作恢复原分组。
- 跳转小节仅在导航时根据已保存内容校验，编辑标题不会误报目标消失。取消常驻未保存/已保存条，保存成功使用3.6秒浮动提示；放弃修改回到工具栏。保存冲突仍明确保稿并提供重新读取。
- 顶栏恢复随记、收藏、问答、统计的顺序，移除额外日志入口；各模块内容工具栏恢复返回日志。恢复搜索宽度、对齐及品牌副标题。
- 随记、收藏使用与问答相同的空状态组件：图标、标题、说明。移除随记空状态的新建按钮；新建保留在正常导航入口。
- 恢复分模块侧栏折叠偏好、折叠筛选浮层、重置与快捷入口；日期标签可定位小节，重复标题使用小节索引区分；恢复日期显示和桌面/手机创建区位置。
- AI面板恢复均分标签、折叠栏当前项、中等宽度下的布局及单一可编辑生成草稿框，移除额外预览/编辑切换。

## 明确保留的调整

“追加到编辑器”保留准确文案：该操作只修改草稿，仍需保存。原“确认写入”容易被理解为已经落盘。

筛选浮层低于危险操作确认层，避免确认被遮挡；溢出菜单触发对话框后，关闭对话框应将焦点还给仍存在的“更多”按钮。外观沿用既有组件。

空状态在各自内容区使用同样的视觉定位规则；手机模块工具栏行数不同，因此不承诺相对整个屏幕的绝对坐标完全相同。

## 验收入口

`ops/browser-ui-parity.mjs`检查文件名样式、顶栏入口、改标题/保存提示生命周期、1920/1440/1180/1024/850/768/390宽度、空状态与模块返回。

`ops/browser-sidebar-parity.mjs`检查分模块偏好、折叠筛选/重置/焦点、AI响应式布局及日期标签导航。既有编辑、恢复、随记、收藏、写作与问答脚本继续检查业务闭环；测试跟随真实可见菜单操作，不强制点击隐藏控件。

本轮只使用合成资料和本机模型替身。独立使用者安装仍是单独的未完成验收项。
