# 明确断开连接（本地候选）

## 契约与实现

按第二阶段配置契约第6节核对：既有“更换连接”只探测和切换候选，并不满足移除当前凭据；“稍后连接”只记录待连接选择，也不冒充断开。

本批在设置“学习记录”提供“断开当前工作台”：

1. 原生确认框说明删除的是此设备当前连接凭据，不是服务端资料；地址和日志／随记草稿保留。存在未提交或未保存的问答编辑时明确提示会放弃。取消不先卸载原工作台或删除凭据。
2. 复用现有切换流程的在途／分类修改门禁、严格日志快照、来源namespace随记收尾及本机草稿保存。将这段已验证的同一职责提为Index私有方法，由切换和断开共用，不另外实现一套草稿逻辑。快照／随记／草稿存储失败不删除凭据或离开A。
3. 新增严格的捕获引用删除。只将本机SDK文档的AssetStore NOT_FOUND（24000002）作为幂等成功；权限、服务或锁屏等错误明确失败并保留当前工作台，不调用吞错的既有clear冒充完成。清理只针对捕获alias，不随当前实例变化误删其他凭据。
4. 成功移除凭据后清空运行中会话、失效模块、关闭设置并进入待连接页，再持久待连接选择；保留非秘密原地址／实例指针和各自草稿。等待期间禁止再开候选或重新连接。若最后偏好写入失败，显示“已断开；待连接选择未能保存，下次启动需重新输入密码”，不假装删除失败或恢复已移除的秘密。

该顺序不声称凭据删除与Preferences是跨系统原子事务。若进程恰在删除成功、偏好保存之前终止，启动时原指针仍可填回地址，但凭据缺失使其要求重新输入密码，不会静默重新登录；可能出现登录表单而不是待连接页。此崩溃窗口及原生AssetStore仍需统筹设备复验。
