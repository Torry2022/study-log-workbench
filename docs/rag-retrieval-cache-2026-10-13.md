# MCP 解析与 BM25 统计复用

重复范围读取原先每次重做所有日志文件的 Markdown 解析；全文检索也每次重新建立标题/正文词频、文档频率和平均长度，混合检索同轮再次排序还会重复建立相同统计。本批分别复用实例内的文件解析结果与最近一组检索语料的 BM25 统计。

文件缓存每次仍执行原有目录和文件安全检查、读取实际正文，再逐字比较；同大小、同修改时间的更新也会重新解析。删除文件移出缓存，解析错误仍报错；跨文件重复日期仍每次检查。返回结果复制，防止调用方修改缓存。继续使用现有 Markdown AST 解析，不退回正则或修改日期分隔规则。

BM25 缓存以参与评分的片段 ID、实际标题和正文的完整指纹失效，不依赖 embedding hash 或查询文字。日期过滤后的语料不同会重新建立统计；查询分词与评分仍每次执行，结果使用当前片段及元数据。缓存只保留最近一组语料，不新增数据库、配置、模型或磁盘文件；重启后首次建立。向量索引、标题权重、排序、融合、引用与原文版本规则不变。

在同机、同一套八个月 224 天合成资料上，重复解析由约 109～117 毫秒降到 13～17 毫秒，重复 BM25 评分由约 80～91 毫秒降到多数 1～2 毫秒（另一次约 16 毫秒）；冷启动仍需解析和建统计。全部排序结果与修改前一致。这是一次受控基准，不代表用户实例或模型生成耗时，证据在 `.local/rag-cache-benchmark-20261013/report.json`。

缓存专项覆盖返回值隔离、同大小同修改时间更新、无效日期、跨文件重复日期、删除、围栏内假日期/分隔线，以及标题/正文变化和日期筛选后的冷暖排序一致。MCP 60 项通过、1 项符号链接权限检查跳过，独立协议冒烟 10 项、Web 问答 205 项、类型检查与生产构建通过。生产入口 13 组通过，已查看 Chromium 深色桌面保存中和 WebKit 浅色手机保存失败截图。

未发布或安装，现有 Windows 隔离候选尚不含本批 MCP 改动。该改善减少检索重复计算，不解决模型长推理、整月历史状态归属或真实向量路径的质量验收。
