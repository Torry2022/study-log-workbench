# 0.1.0 正式版发布记录

0.1.0 是学习日志工作台的首个正式版本，包含 Windows x64、本地与 Linux amd64 自部署服务，以及连接自部署服务的鸿蒙客户端源码和未签名 HAP。版本内容以 `v0.1.0` 标签为准，rc.9 及更早预发布保持不变。Release 正文先说明整个版本已经具备的日志、随记、收藏、统计、问答和多端能力，再列正式版相对候选版的收尾变化。

## 验证范围

- Web 类型检查和生产构建通过。
- 网页动效与加载反馈在 Chromium、WebKit 的浅色、深色、桌面和手机布局下完成检查，覆盖正常动效、减少动效、连续切换、慢请求、失败重试和稳定内容保留；分屏源码在左、浏览在右，编辑菜单在桌面高度充足时无需滚动。
- Windows 最终包通过本地实例、二次启动、编辑保存、草稿关闭保护、正常重开、完整备份恢复和服务异常收尾检查。
- 三份 Linux amd64 镜像通过隔离 Compose 初始化、认证、日志与随记读写、材料资源、维护锁、只读 MCP、停止和同版本归档恢复检查。
- 鸿蒙客户端 243 项协议检查和 release HAP 构建通过；问答生成期间切换模块及历史项运行状态已有专项覆盖。公开仓库没有签名材料，本轮没有把新产物安装到设备，不将无签名构建记为真机安装通过。
- 全部检查使用隔离合成资料，没有写入真实日志或调用付费模型。

## 发布前界面调整

分屏模式最终调整为源码在左、浏览在右，保留原有同步滚动与各自滚动区域。源码编辑菜单在窗口高度足够时完整展开；高度不足时才滚动。编辑入口使用深色编辑器内的次级按钮样式，避免浅色按钮割裂编辑区。对应 Chromium、WebKit 浅深色检查、Markdown 菜单操作检查、桌面完整流程和 Linux Compose 检查均通过。

## 同版本启动修正

首次公开附件安装后，实际旧运行状态暴露出 Windows `LastBootUpTime` 在同一次开机内查询会相差约 1—2 秒。原实现要求时间完全相等，因而拒绝了本可安全恢复的旧状态。修正后只将 10 秒以内的差异视为同一次开机的测量误差，其余进程身份、工作进程、机器、目录、实例、未完成写入和并发恢复检查保持不变；旧状态仍移入恢复记录而非删除。7 项恢复专项测试和最终安装包完整桌面流程通过；实际遗留状态恢复后，修正包覆盖安装并正常启动本地 Web、MCP 与工作台，页面返回 HTTP 200。
