# 首轮核对截断后的处理

实验首轮生成以 `length` 结束时，丢弃未完成的 JSON、答案和缺口判断，记录首轮用量及 `firstPassLimited`，继续已有的只读取证循环。没有重发首轮请求，不增加工具轮数或整轮超时。工具仍只能依据保留的日志、原有日期及字面约束行动；结束后单独生成完整的最终回答。

这不是把不完整答案当作成功。首轮过滤、非法结构、鉴权、限流、网络和取消仍按既有规则失败；工具阶段及最终答案的完整性保护不变。首轮判断被截断本身不代表日志缺失或读取覆盖不足，因此不改写资料覆盖状态。是否需要补查、能否完成回答仍须实际核对。

合成专项经真实 MCP 和 SDK，验证半截文本不进入工具状态、SSE 正文及来源，首轮用量保留，现有工具循环结束后才发送完整答案。已有短题一次调用、来源、范围、取消及错误检查保持。166 项 RAG 回归、类型检查及生产构建通过。

Windows 候选 Node 22.23.3 运行当前共享生产构建，正式接口五组以及 Chromium/WebKit 浅深色四组共九项通过；浏览器也执行首轮截断路径并完成保存，截图已查看。证据在 `.local/rag-entry-production-1791786104150/`。模型替身只证明流程，不替代真实模型质量评估；实际资料和派生评估不提交 Git。
