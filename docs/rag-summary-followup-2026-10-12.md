# 短规则保留与长材料复测

## 修复

核对实际 MCP 读取：范围接口已按不超过 30000 字的页面分段，客户端同样校验容量。因此没有引入第二套长日分段器。

原压缩流程会将短规则与长片段一起送去摘要；同批摘要失败还会把短规则标成截断。现保留不超过每条预算的原文，只压缩需要缩短的片段。每条预算仍为 `min(900, floor(30000 / 来源数))`，总材料上限不变。条件、否定、来源身份和原文摘录不被程序改写；摘要提示补充保留后续查找的规则名称。摘要失败仍如实标记受影响的长片段，不宣称读全等于答全。

## 真实复测

沿用前轮四个月合成资料和既定题目，最终模型 deepseek-flash，reasoningEffort=none，不调用 Jev、不操作真实记录。本轮仅复测普通措辞多步题及完整范围，各计划两轮基础 RAG/实验 Agent 对照；总预留上界 1.4 元。

- 多步题两次 Agent 都搜索后因无新增证据停止，没有读到末尾线索；两次基础 RAG 也缺少具体条件。新增工具状态信息未证明可重复收益，不能默认启用。
- 完整范围首轮两条路径均读全两天、保留三个保存条件与不能自动保存的限制，各三次模型调用，均跳过 Agent 补查。短规则保留原文符合预期，但单轮不能证明整体无退化。
- 完整范围第二轮基础路径在压缩阶段遭代理预算拒绝，仍以部分材料回答；接着实验路径也遇到代理拒绝并返回 error。本轮如实保留这些失败，不能按 done 认定范围质量通过，也不能把验收预算不足当成模型工具不支持。

共实际转发 17 次模型调用，用量折算上界 0.47743 元，没有未结算预留；该数值不是供应商账单。报告：`.local/rag-summary-followup-1791734627556/`，来源文件哈希未变。没有付费重试。

根据本次代理拒绝的证据，验收脚本改为每题结束后检查拒绝列表；出现拒绝立即终止后续题目。拒绝可能已发生在同一题的摘要阶段，必须检查该题记录，不能事后把受影响的回答当作质量成功。

## 本地验证与下一步

149 项问答测试及生产构建（含类型检查）通过。新增测试检查长片段之间和末尾的短规则，在摘要成功/失败两种情形下均保留原文、版本身份与非截断状态，并保持总容量。

实际生产问答接口和独立 Chromium/WebKit 浅深色页面替身检查七项通过，证据：`.local/rag-entry-production-1791734671356/`。此入口检查不替代真实模型质量对照。本批未打包 Windows、发布或安装。

下一步针对已有截断片段且问题缺少具体依据时，模型为何仍优先重复搜索，检查工具选择提示和提供给它的可读来源信息。继续沿既有两轮/八次工具预算改进，不增加额外必经判断模型；完整范围后续只比较没有代理拒绝的完整试题。问答目标仍未完成。
