# Windows 桌面试用版

安装后从快捷方式打开，无需另开浏览器、安装 Node 或手动启停服务。桌面端沿用现有网页工作台与 Markdown 存储格式，支持本地使用或连接已部署的服务器。当前为未签名的预发布安装包。下载 [Windows x64 安装包](https://github.com/Torry2022/study-log-workbench-public/releases/download/v0.1.0-rc.3/study-log-desktop-0.1.0-x64-setup.exe)，版本说明及 SHA-256 校验文件见[预发布页面](https://github.com/Torry2022/study-log-workbench-public/releases/tag/v0.1.0-rc.3)。

## 开始使用

1. 首次打开选择“本地使用”或“连接服务器”。本地模式可直接使用建议的资料位置，也可选择其他文件夹；空文件夹用于新建资料，已有有效实例可直接打开，普通非空文件夹不能初始化。
2. 进入工作台，点击“今天”写下学习内容并保存。未配置模型也能记录、编辑和检索日志。
3. 关闭应用时，未保存内容会询问是否离开，所属本地服务随后正常停止。以后打开会沿用已确认的使用方式和资料位置；重复启动会激活已有窗口。

本机使用现有认证接口自动登录，不要求输入服务密码；这依赖当前 Windows 用户对配置文件的访问权限，并非额外的本地应用锁。服务仅监听本机，HTTP 接口认证仍然有效。

## 历史版本与整份备份

日志历史版本用于恢复误改的某一天，默认保留在实例内。进入“文件 → 日志历史版本…”可关闭后续记录或设置保留期限；关闭不会删除已有版本，已有版本仍可从日志页“历史版本”查看和恢复。设置期限后，仅在后续成功保存对应日志时清理其过期版本。

整份资料备份由用户主动执行，默认不会自动创建。需要时选择“文件 → 备份全部资料…”，将归档另存到资料目录以外的位置；要防范磁盘损坏，还应保存在其他磁盘或设备。历史版本与原资料同处一个实例，不能代替独立备份。

归档包含实例配置和密钥，请妥善保管。备份与恢复会先正常停止本地服务，完成后重新打开工作台；模型和历史版本设置保存后也会重开，未保存内容仍需确认。

正常卸载只移除程序，保留资料；重装可继续打开原资料。资料位置丢失、实例锁遗留或服务异常时，不会自动删除锁、清空或重新初始化已有资料。不要将异常锁当作可直接删除的临时文件。

## 版本与更新（下一候选 rc.4）

“帮助 → 关于学习日志工作台”分别显示桌面与当前服务版本；连接旧服务器时可能显示“未提供”。本地服务随安装包一起升级，服务器由实例维护者更新。服务器更新后重新打开窗口即可加载网页，桌面外壳仍需更新安装包。

## 开发与验收

在 Windows x64 构建，先安装网页与检索服务依赖，执行网页类型检查、生产构建，再运行：

```powershell
npm ci --prefix ops/electron
node ops/electron/node_modules/electron/install.js
npm run package:electron
npm run desktop
npm run test:electron
```

打包复用 `ops/desktop/package-windows.mjs` 的固定 Node 运行时和 Web standalone／检索资源。输出目录必须是新的；已有 `.local\electron-payload` 不会被自动覆盖或删除。安装包输出位于 `.local\electron-dist`，不上传源码仓库。构建失败可在核对已准备资源后单独运行 Electron Builder，无需重新生成同名资料目录。

`STUDY_LOG_DESKTOP_PROFILE` 可为自动验收显式指定独立的绝对路径，使偏好与资料均与日常使用隔离。`ops/electron/smoke.mjs` 默认创建临时合成实例；传入已打包 EXE 绝对路径可对真实包复测。测试不安装到日常目录，不调用付费模型。

窗口保持沙盒、上下文隔离与禁用 Node 集成；网页只得到关闭窗口的最小接口。服务配置和密钥留在主进程／所属服务，不通过桥接接口返回。退出沿用私有 IPC 正常停止，实例锁仅在正常结束后释放。

本机真实 NSIS 首次安装、同版本覆盖安装、卸载保留默认资料、重装读回已完成。安装包尚未签名或公开发布；两个候选同为 0.1.0，此结果不代表跨版本数据迁移或安装向导的人工视觉验收。

## 本地与服务器（2026-10-07）

首次打开可选择“本地使用”或“连接服务器”；已有桌面实例继续打开原资料。之后通过“文件 → 使用方式…”切换，未保存内容仍需确认。标题栏显示本地资料或服务器地址，窄窗口可从使用方式窗口查看完整位置。

本地模式由桌面程序管理本机服务。服务器模式只连接现有公开版实例，不启动本机 Web／检索服务；Windows、浏览器和鸿蒙读写服务器上的同一套资料。两种方式不是同步开关：本地资料不会上传、合并或随服务器变动。服务器模式不开放本地目录、模型配置及整实例备份恢复菜单；页面已有的日块备份和内容导出仍按服务器能力使用。

服务器地址沿用鸿蒙规则：HTTPS，可含 `/study-log`；不接受账号、查询参数或其他路径。仅显式勾选后允许本地／局域网 HTTP 测试。正常校验证书，不提供忽略证书错误的选项。连接使用现有 Web 密码接口及 capabilities 协议；密码不写入桌面偏好，登录 Cookie 保存在按地址和实例身份隔离的浏览器会话中。重开先校验身份；登录失效、无法连接或身份变化时回到连接入口，不自动改用本地资料。

### 从本地迁移到服务器

1. 保存记录，通过“文件 → 迁移到服务器…”进入整实例备份。归档和对应 `.sha256` 文件一起保管；其中包含配置及凭据，不是公开分享文件。
2. 使用安全传输把两份文件交给服务器维护者。按 [整实例恢复](backup-restore.md#恢复到新实例) 恢复到一个尚不存在的新目录，不导入或覆盖已有服务器实例。
3. 维护者按服务器部署文档调整新实例的运行配置：访问密码、HTTPS Cookie、检索服务地址／凭据及容器路径。桌面生成的本机配置不能直接照搬为公网配置。更改访问密码／会话密钥后需要重新登录，不更改实例身份和源日志。
4. 启动恢复出的服务器实例，从 Windows“使用方式”连接，核对日期、正文、附件、随记、收藏等。确认后让鸿蒙连接同一地址；之后以服务器为日常记录位置。本地原目录及备份保留。

## 日志历史版本与整份资料备份

首次使用只选择资料位置，不设置自动备份。整份资料归档仅在用户执行“文件 → 备份全部资料…”后生成，保存位置由用户选择；没有后台自动归档。

“文件 → 日志历史版本…”管理日志修改前的历史副本，默认开启且不限期限。关闭仅停止生成新版本，已有版本仍可查看和恢复。可选保留 30/90/180/365 天；保存设置会通过原有关闭流程处理未保存内容、停止服务、原子更新实例配置并重新打开。服务器模式不开放本机历史设置。

配置写入该实例 .env 的 LOG_HISTORY_ENABLED 和 LOG_HISTORY_DAYS，缺省为 true / 0；0 表示不限期限。日志成功写入后按源文件清理过期的当前格式历史快照；失败或冲突的写入不会触发清理。旧格式版本、其他源文件、随记事务恢复副本、配置副本和导出归档不删除。清理失败不会把已成功写入报告为失败，会在后续保存时重试。设置本身不会立即清理资料，默认不删除现有历史。

这些历史副本仍位于实例内 backups，用于误改恢复，不能应对整份资料丢失或磁盘损坏。日志页入口统一称“历史版本”，与独立归档区分；不改 API 或旧客户端协议。
