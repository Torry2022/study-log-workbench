# 0.1.0 鸿蒙端核查与交付

本轮以网页、Windows 和服务端 0.1.0 的最终状态为基准，逐项核对鸿蒙客户端。目标是补齐实际缺口，并把可复核的鸿蒙构建产物纳入首个正式 Release；网页专属 CSS、Windows 标题栏及本机服务恢复逻辑不移植到原生客户端。

## 核对结果

| 范围 | 结果 |
| --- | --- |
| 五个工作区模块 | 日志、随记、收藏、问答和统计均已接入自部署服务器。 |
| 日志阅读与编辑 | 原生端已有浏览、源码、分屏、格式操作、目录、历史版本、图片、导出和返回顶部；分屏已经是源码在左、浏览在右。 |
| 视觉与交互 | 当前 Logo、主题底色、右侧检查器切换、加载与工作区过渡已有原生实现；不照搬网页 CSS 动效。 |
| 统计分类 | 已采用 AI 先提出建议、使用者审核调整的流程；未配置模型时保留基础统计。 |
| 问答协议 | 来源指针、日期范围、引用及当前服务端 RAG／Agent 能力通过同一 API 获得，不在客户端重复实现检索器。 |
| 后台回答 | 本轮允许回答生成期间切换到其他模块，并在对应历史会话上显示运行状态。当前控制器仍一次管理一个问答会话，因此生成期间不能切换到另一问答会话。 |
| 平台专属变化 | Windows 运行状态恢复、系统标题栏和安装流程，以及网页滚动条、WebKit 后备动效等不适用于鸿蒙原生端。 |

## 本轮修改

- 移除生成回答时离开问答模块的阻止，让已发出的请求在挂载的问答页面中继续完成和保存。
- 在问答历史项显示运行中的加载标记，离开问答模块后仍能看出哪一条会话正在生成。
- 保留未提交问题和未保存回答的离开保护；生成期间暂不允许切换问答会话，以免单会话控制器把回答写入错误记录。
- 补齐 release 构建引用的空混淆规则文件；混淆继续关闭，不改变产物代码。

## 验证

- `npm run test:protocol`：243 项通过。
- release `assembleHap`：通过，产物为 `entry-default-unsigned.hap`。
- 构建仍有既有 API 兼容及重复资源 ID 警告，没有构建错误。
- 产物未签名。公开仓库不包含证书、私钥和 Profile，本批没有把新产物安装到已连接设备，因此不把构建成功写成真机安装通过。

Release 附件使用名称 `study-log-harmony-0.1.0-unsigned.hap`。使用者需要按客户端 README 配置自己的签名；签名身份、包名和目标设备 Profile 必须匹配。
