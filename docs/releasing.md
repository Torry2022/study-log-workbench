# 版本与配套发布

每个发布候选使用明确版本，例如 `0.1.0-rc.4`。桌面端、Web、MCP 及根目录 package.json 与各自 lockfile 的根包版本同步；GitHub 标签加 `v`，ACR 标签不加。应用内产品版本与接口 `apiContractVersion` 职责不同，不因普通更新递增接口契约。

## 发布范围

- Web/API 或检索改动影响本地使用时，同批构建 Windows 安装包与配套 web、mcp、tools 镜像；验证后再提供同版部署附件。
- 仅桌面外壳修改可以只发 Windows 包，不为保持数字一致而改写既有服务器镜像标签。此时“关于”中的桌面和服务版本不同是正常的。
- 文档修订不必重建产品；版本说明列明产品基线。固定标签和已发布附件不得用不同内容覆盖。

## 发布步骤

2026-10-10 维护者明确要求将起步引导视觉修正替换到 rc.9；本次按此授权替换相应标签、附件及 web 镜像，保留旧附件和证据。mcp／tools 内容不变，详见[例外记录](onboarding-layout-2026-10-10.md)。后续普通更新仍使用新版本。

1. 更新本轮产品版本及 lockfile，核对适用平台，完成受影响测试与构建。版本设置必须在构建之前完成。
2. 本地模式验证整体安装包；服务端用配套 Compose 验证隔离实例初始化、读写、停止及新目录恢复。更新前备份，不用强杀或删锁处理升级失败。
3. 用新标签发布镜像并验证匿名拉取；更新 deploy/.env.example、版本说明和摘要。只改桌面时跳过此步骤。
4. 创建 GitHub 草稿 Release，附 Windows 安装包、适用的服务器部署包与 SHA256SUMS.txt；核对上传摘要后才公开。预发布标记必须与版本一致。
5. 更新 README 下载入口，验证公开下载可达。记录实际基线和未验项，不将同版本恢复写成跨版本迁移通过。

Windows 更新检查读取本项目最近 100 条 Release，忽略草稿及没有 Windows 安装包的发布。它只引导人工下载，不承担服务器更新、资料同步或自动安装。预发布用户可看到后续预发布与正式版；正式版用户不自动进入预发布通道。
