# 删除日志后的日期选择

## 缺陷与修正

日志删除成功返回 `exists: false` 的日对象。共享工作区原本通过保存／历史恢复的接收函数处理它，更新列表但保留原日期和空草稿；因此日期已从侧栏消失，标题仍停在该日，保存还可把空日重新创建。旧生产构建独立复现：删除 2026-10-08 后标题仍为该日，期待剩余 2026-10-09 的断言失败，见 `.local/log-delete-before.log`。

删除成功改走 `useLogWorkspace.acceptDeleted`：清除当前月、日和标题定位，移除地址中的已删日期，清除旧列表与当前日，随后复用原有月份／日期读取选择剩余日志；无剩余记录则进入正常空状态。草稿先接受删除结果，清除已确认放弃的修改。收藏继续按原机制重新读取。取消或请求失败不执行状态重置，版本校验与服务端存储规则不变。

本批不改变新建日期、读取不存在日期或保存空日志的现有规则；只修正用户明确删除成功后的行为。没有操作维护者真实日志。

## 验证

- Web 类型检查及生产构建通过：`.local/log-delete-typecheck.log`、`.local/log-delete-build.log`。
- 独立 `ops/electron/log-delete-smoke.mjs` 在合成工作台操作实际删除按钮和确认弹窗，源码 Electron 与普通 Chromium 均检查：取消、模拟 500 失败、未保存草稿取消、同月剩余日期、跨月剩余日期、最后一天删除、删除后刷新。全部通过，无页面异常，见 `.local/log-delete-1791547286528/report.json`。
- 人工查看删除后剩余日期和全部删除后的截图，标题、日期列表、保存状态及空状态一致。首次脚本误用可见文本“删除”查找具有 `aria-label="删除当前日志"` 的按钮，超时；修正定位后完成缺陷复现及同一流程复测，没有降低状态断言。

改动位于共享 Web 工作区，Windows 继续加载同一实现；鸿蒙原生删除入口未改。本批未打包、推送、发布、部署或覆盖安装，当前日常应用尚未包含该修正。
