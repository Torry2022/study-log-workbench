# 取消工具决策单独的输出长度限制

此前为工具决策设置的 1200 tokens 是项目自行添加的限制，不是供应商要求或维护者授权的费用预算。思考内容也占输出长度，这个较小的独立限制可能在工具动作完成前截断决策。

工具循环现在不单独传 `maxOutputTokens`/`max_tokens`，沿用所选模型的默认输出限制，与普通 RAG 最终生成的请求方式一致。首轮结构化回答/缺口输出已有的 8192 上限没有改变。两轮工具决策、八次 MCP 调用、120 秒整轮超时及内部消息隔离保持；供应商仍可能以 length 结束，届时按已有逻辑停止补查并报告受限状态，不发布截断的内部内容。

验收侧费用代理仍独立限制单次测试输出并在请求前预留费用，不把测试支付保护当作产品输出配置，也不扩大追加费用授权。取消独立 1200 限制不证明取证方向、材料选择或最终结论正确，质量对照继续，默认 Agent/Jev 保持关闭。

164 项 RAG 回归、类型检查及生产构建通过。使用 Windows 候选自带 Node 22.23.3 运行当前生产构建，正式入口四组与 Chromium/WebKit 浅深色四组共八项通过；工具请求不再包含单独的 max_tokens，仍覆盖输出截断后的受限最终回答、来源及内部文本隔离。报告在 `.local/rag-entry-production-1791781746065/`。不纳入实际用户资料及其派生内容。

安装包需在后续最终候选中更新；上述检查运行的是当前共享生产构建，不能宣称较早的安装包已包含本次取消限制。未推送、发布或覆盖安装，鸿蒙本轮未改。
