# 问答入口与取证决策对照

## 改动与边界

实验 Agent 不再依赖“为什么、如何”等问题用词；初次搜索尚未读完整范围且不是精确字面检索时，由同一有界工具循环选择补查或结束。已完整读取的范围仍直接整理并回答。两个实验开关仍须同时开启，默认未启用；没有加入额外路由模型或 Jev。

每轮重建模型输入时，提供结构化已执行请求、剩余决策轮数、上一工具新增来源编号及每个片段的截断标记。工具正文和临时文本仍只留在服务端，两轮决策、累计八次 MCP 调用以及共享取消不变。最新状态信息修改仅完成替身检查，尚不能声称改善真实模型质量。

## 真实对照结果

使用 `scripts/rag-entry-corpus.mjs` 预先生成四个月的隔离合成资料，全部资料始终对检索可见。包含三个同义问法、长排错记录、已有充分依据的短排错/读书记录，以及完整日期范围。每组重复两次，比较普通 RAG 和实验 Agent，最终模型均为 deepseek-flash，reasoningEffort 为 none；未调用 Jev 或使用真实日志。

七组共 28 次问答、71 次上游模型调用返回完成，来源文件哈希未变。这只是流程结束证据，不是质量通过。报告保留在 `.local/rag-entry-evaluation-1791733322478/`，合成材料在 `.local/rag-entry-corpus-1791733190384/`。

- 归档问题的六次 Agent 回答中，三次取得另篇规则中的保存条件，另外三次仍只找到规则名称或提前停止。普通 RAG 六次均没有具体条件，正确说明材料不足。取得条件的答案仍有把过程采样当成原因的表述问题，不能将取得来源等同于回答全部正确。
- 长排错记录两次 Agent 中一次读到另篇检查说明，另一次提前结束。普通 RAG 两次均缺少说明。这证明多步取证有潜在收益，但收益尚不能重复稳定获得。
- 已有足够材料的短排错和读书题，两条路径都能回答，Agent 额外增加一至两次模型调用，未观察到实质收益。
- 完整范围题初始已覆盖两天；材料压缩后却出现补查。验收代理当时余量可能无法承受大请求的最坏预留，压缩失败会截断并标记受限。旧报告未记录代理在转发前拒绝的请求，不能排除预算干扰，因此这组不能作为范围质量或无退化的证明。

七组用量折算上界合计 1.75189 元，无未结算预留；这是验收工具的保守核算，不是供应商账单。结算由旧费率改为与预留一致的每百万输入 5 元、输出 20 元，避免释放过多预算。[官方价格](https://api-docs.deepseek.com/quick_start/pricing/)为美元计价；当前折算上界采用保守的 10 元/美元假设，而非实时汇率。

验收代理现另外记录转发前的拒绝类别和耗时，不记录请求正文或密钥。预算不足、调用上限和请求体积限制可与供应商实际调用分开核对。原真实报告没有这些字段，不能事后补造。

## 当前结论与下一步

最终源码的 148 项问答测试、5 项预算代理测试、生产构建（含类型检查）通过。`node ops/verify-rag-entry.mjs` 使用实际生产 API、实际 MCP 和替身模型：三次鉴权接口检查确认普通事实问法进入实验循环、字面检索与完整月份跳过；独立 Chromium/WebKit 浅深色四次实际页面提问完成回答、来源和会话保存。证据在 `.local/rag-entry-production-1791734220340/`，已实际查看浅色 Chromium 和深色 WebKit 截图。首次验收脚本缺少安全长度的会话密钥和实例身份文件，修正隔离资料配置后重跑；早期失败未计为产品通过或缺陷。本批没有 Windows 打包、安装或真实模型重试，不能据此声称这些已完成。

入口已解除措辞门槛，替身证明三种问法能够沿相同线索读到具名规则。真实模型还会重复搜索、遗漏线索或过早结束，简单题额外调用也有成本，尚不满足默认启用标准。

下一步核对新增状态信息是否能改善决策，同时检查长材料压缩保留条件与线索的效果。完整范围需在充分且可核对的预算下重新比较；后续实际对照必须分别报告代理拒绝、模型调用、材料覆盖和回答质量，不能只按 done 计通过。不增加必经判断器，也不靠扩大循环次数掩盖失败。
