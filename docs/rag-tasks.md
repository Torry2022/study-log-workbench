# 持久问答任务

持久问答任务已纳入 0.1.3：服务端执行、网页与鸿蒙任务管理、容器归档恢复及旧版保护已实现。新版 Windows 原位覆盖、实际安装入口、Linux 配套三镜像及真实平板列明流程已完成验收，手机因锁屏待验。具体产物与独验范围见[0.1.3 发布记录](release-0.1.3-2026-10-19.md)；以下分阶段记录保留原时间点的边界。

## 执行与存储

Next.js 的 Node 启动入口登记实例级执行器，数据库为明确配置的 `LOG_ROOT/state/rag-tasks.sqlite`。执行器在页面连接之外调用现有 RAG／Agent，不增加模型规划步骤或改变长材料处理能力。

受理首个任务前，先用原会话锁及原子替换写入收据集合，即使此时集合为空。写入失败就不受理任务、不调用模型；旧版会话写入器也因此能在首个结果产生前拒绝不认识的格式。

任务先落盘，再认领执行。正常空闲时立即认领，最多一个活动问答和八个等待任务；旧 `/api/rag/query` 与任务共用执行名额。取消后须等上游清理结束才释放名额。任务仍受原问答的超时、来源及调用限制约束。

若执行过程已经结束，但临时存储故障使终态未能写入，同一存活执行器在后续 tick 中也会核对并标为中断，释放对应名额，不重放模型。核对以本 owner 是否仍有登记的执行过程为依据；模型仍在等待时不会仅因长时间没有进度被终止。

支持单机、单实例运行，不提供跨机器调度。执行代次阻止旧执行器覆盖新状态；SQLite 事务保护认领和状态变更，进程所有权与租约用于恢复。启动时把遗留执行中任务标为中断，不自动再次调用模型。尚未开始的等待任务可以继续执行。

数据库保存任务身份、输入快照、执行阶段、周期落盘的片段、完整结果、引用、已返回诊断和会话保存状态；不保存模型密钥。跟进问题的历史取自经版本核对的服务端会话，新会话不能靠未保存的客户端历史继续。相同提交标识和相同请求返回原任务，不重新理解历史或生成答案；内容不同则冲突。

任务没有新增的自动结果清除期限。显式删除任务，或删除其所属会话，会清除任务中的问题、历史、片段及结果；保留最小身份和指纹，阻止迟到重试重新执行。沿用既有会话备份规则，不把这项清理表述为备份删除或磁盘取证意义的彻底擦除。数据库有容量限制，达到限制时拒绝新任务，不默默清除未保存回答。

## 结果写入与恢复

日志 Markdown、附件、历史版本及检索索引仍保持原有权威边界。任务不会自动写正式日志。问答会话仍为 `state/rag-sessions.json`，任务库不另建一份可编辑会话。

完整回答先写入 SQLite，随后按提交时的会话版本追加或重新生成最后一对消息。不同版本不覆盖；唯一可自动衔接的版本变化是程序确认的自动标题更新，其指纹绑定更新前的版本。手动改名、正文或回答模式变化仍冲突。生成成功而保存失败时，完整结果仍在任务中，只重试保存。删除标记优先于任务保存，任务不能复活会话。

会话消息和任务收据放在同一次 JSON 原子替换中。JSON 已替换、SQLite 尚未登记保存成功时进程终止，下次根据收据确认，不再次追加消息。收据落盘后的其他会话编辑也不会被恢复过程覆盖。JSON 删除标记先提交，任务清理失败则由重试或执行器再次核对恢复。

会话写入使用项目内的独立 SQLite 互斥文件 `state/rag-sessions-lock.sqlite`，由 SQLite 释放崩溃进程的文件锁；不再自行回收 PID 文件锁。它不存放会话正文。只读会话读取依赖原子 JSON 快照，不为读取空实例创建状态文件。

Windows 的原子替换若暂时返回 `EPERM/EACCES/EBUSY`，在原会话锁内最多追加三次重试，总退避 175ms；每次重新检查原文件，沿用同一个临时文件和备份。持续失败仍保留原快照并返回保存错误，不绕过权限或重新生成回答。

## API 与查看协议

路径均位于 `/study-log/api`，沿用现有 Cookie／App Bearer 鉴权。

| 接口 | 用途 |
| --- | --- |
| `POST /rag/tasks` | 提交 `submissionId`、`sessionId`、`baseVersion`、`question`、`mode`，可用 `replaceLast` 重新生成末次回答；返回任务快照 |
| `GET /rag/tasks` | 返回轻量摘要：全部活动任务、全部待保存／保存失败／保存冲突的成功结果，以及按创建时间倒序最近 100 项其他终态历史；完整片段和答案另按 ID 查询 |
| `GET /rag/tasks/:id` | 查询单项快照 |
| `GET /rag/tasks/:id/events` | SSE `snapshot`，`id` 为持久修订号；`after` 或 `Last-Event-ID` 用于重连 |
| `POST /rag/tasks/:id/cancel` | 主动取消；已完成的任务保持完成 |
| `POST /rag/tasks/:id/save` | 仅重新尝试会话写入，不生成答案 |
| `DELETE /rag/tasks/:id` | 删除任务内容，不代替删除已保存会话 |

状态为 `queued/running/succeeded/failed/cancelled/interrupted`。成功另有 `pending/saved/conflict/error` 保存状态；查询到生成成功不能直接视为会话已保存。失败结果和片段也不能当作完整答案。

订阅连接取消、关闭或登录过期只停止查看，不取消服务端任务。主动停止必须调用取消接口。重连读取最新快照，不重放每个 token；客户端以修订号去重并替换片段，不能把快照反复追加。完整快照另带 `replaceLast`，恢复重新生成任务时不会在旧回答后再追加一对。旧问答的 `status/sources/delta/done/error` 协议保留。

模型请求已返回响应头时，取消与期限到达仍会显式取消正文 reader，不能只依赖 fetch 关闭连接。执行资源在上游清理后释放；任务显示已停止不单独作为连接已释放的证明。

## 网页接入

网页检查 `/capabilities` 的 `ragTasks`。能力未声明时使用原请求流与客户端保存；声明支持但执行器未就绪、协议版本未知时阻止发送，不静默退回非持久请求。

提交前把原 `submissionId`、会话版本、问题、模式及重新生成标记保存在当前 origin 下、按 `instanceId` 分开的待确认记录中。不保存答案或完整聊天历史。浏览器存储不可写时不发起首个任务；响应丢失后先查任务列表，必要时以原提交身份重试。确认受理后清除本地待确认记录；用户在确认期间点击停止，会先保留停止意图，再取消对应任务。

任务请求携带 `X-Study-Log-Instance`，服务端在执行前核对，防止同一地址换成另一个实例后重放旧请求。未发送该头的既有 API 调用保持兼容。

网页每秒读取轻量任务列表，仅在修订号改变时获取完整快照；已保存历史通过会话接口读取。同页重新登录时，新查看连接继续核对工作区原先已知的任务，即使它在断开期间完成，也不能直接跳过而留下旧的生成状态。其他浏览器登录同一实例后也能发现活动任务及未保存结果。侧栏沿用生成、保存、未保存和新回答反馈。离开模块、刷新、关闭或重新登录不会取消服务端任务；显式停止才发送取消请求。

生成成功但未写入会话的完整结果按任务 ID 分别保留，不因同一会话出现更新的任务而合并或丢弃。会话内的“查看回答”可以选择旧结果或返回已保存会话；默认仍显示最新问答。查看旧结果时只展示它自己的问题、答案和引用，新的任务进度不会切走用户的选择。刷新后及其他浏览器仍可发现并选择这些结果。复制、保存重试、停止和放弃使用所选任务身份；放弃一项不影响同会话其他结果或已保存内容。任务／会话已确认删除后，迟到的旧快照不得重新登记到工作区。

答案由服务端写入会话，任务路径不再发客户端会话 POST／PUT。完整结果保存后读取服务端会话，包括另一端之后的修改；快照使用稳定的消息身份替换，不重复追加。生成失败由用户重试新任务，保存失败只调用 `/save`。版本冲突不提供覆盖保存；可复制回答，或确认放弃该未保存任务结果后重读会话。

自动标题继续异步执行，不阻塞下一问。仅发起任务的网页尝试自动标题，其他查看者不重复调用；发起页面已关闭时可能保留首问生成的回退标题，仍可手动改名。标题失败不影响完整回答保存。

## 鸿蒙候选接入

`QaTaskClient` 负责发现、轮询、提交恢复及任务操作，`QaSessionController` 继续管理当前会话的展示。离开页面只停止查看；重新打开客户端时，从服务器发现活动任务、未保存结果及已保存会话，不依赖旧页面继续存活。当前会话生成时可以切换其他会话，等待任务沿用服务端队列；侧栏分别合并任务状态与权威会话列表，普通列表刷新不清掉活动或未保存结果。

原生连接使用与网页相同的能力边界：未声明或不支持任务协议时沿用旧 SSE／版本化客户端保存；声明支持但未就绪或版本未知时阻止发送，不静默改走旧路径。任务路径不调用客户端会话写入，也不把取消、失败或中断片段保存为成功回答。

待确认提交通过 Preferences 按服务器 origin 和 instanceId 对应的本地 namespace 保存，包含原提交身份、问题、模式和会话版本，不保存答案或完整历史。发送及重开恢复前先确认 flush 成功；受理响应丢失时复用原身份。任务请求带实例身份头，协议客户端还绑定创建时的原生连接代次，防止旧页面操作落到已切换的连接。

会话内的“查看回答”可选择较早的完整未保存结果，历史结果单独展示自己的问题、答案和来源。“重试保存”只写对应任务；冲突不提供覆盖操作。放弃经确认后仅删除所选结果；停止和显式生成重试也使用各自任务身份。生成重试使用新提交身份，沿用原任务的 `replaceLast`：原为重新生成就替换末轮，普通提问仍追加；待确认期间也按同一语义展示。权威会话读取失败时保留已显示结果、提供重试，并阻止下一问使用旧版本。确认删除后，迟到响应不能恢复该会话或结果。原生端沿用回退会话标题，不新增自动标题调用。

## 归档、恢复与回退

只支持停机归档。正式 Web 入口在整个运行期间持有实例维护锁，在线归档会被拒绝；停止 Web、MCP 及外部写入后，归档在同一维护锁下保存 SQLite、JSON 收据及其他实例文件。JSON 已写入而 SQLite 尚未确认的快照也可恢复，原收据会阻止重复追加回答。

含任务库的归档使用清单版本 2，旧维护工具会在创建恢复目录前拒绝它。当前工具仍接受版本 1；不含任务库的实例继续生成版本 1 归档。恢复到新目录时，旧执行和等待任务统一标为中断，保留片段和已完成结果，清除旧执行权及租约；JSON 收据与消息不变。普通服务重启仍可继续排队任务，这与从归档恢复不同。

损坏或新于当前支持版本的任务库会使恢复停在未完成状态，保留目标、标记及维护锁，不把不明任务状态交给服务执行。正常打开任务库时也先检查版本，再设置日志模式，不能为拒绝新格式而先改写它。

旧版 v0.1.2 可以明确拒绝带收据的会话文件，但不能继续管理这些问答状态。需要回退时应保留当前实例，用升级前的完整归档恢复到另一个目录；不要删除任务库、收据或强行修改版本号来绕过保护。该边界不等于所有历史版本都兼容。

## Windows 候选包

远程模式只查看服务器任务，不启动本地 Web／MCP；关闭窗口后服务器继续生成并保存，重开或其他浏览器可发现同一任务和结果。本地模式使用随包 Node 运行 Web／MCP，正常退出应用会停止本地服务和上游请求；已生成片段留在任务库，重开显示中断，不自动重放模型，也不把片段保存为成功回答。

生命周期专项入口为 `ops/electron/rag-tasks-smoke.mjs`，由候选包或已安装程序的 `resources/payload/runtime/node.exe` 执行，以对应 EXE 及已验收源码清单路径为参数。脚本创建独立用户目录、两个合成实例和本机模型替身，操作实际 Electron 窗口与独立 Chromium；同时核对包内 Node 身份、SQLite 落盘、服务进程归属、来源不变及任务路径没有客户端会话写入。它不运行安装器。专项也覆盖等待 15 秒后实际点击取消、释放上游与租约，以及长等待后本地正常退出；浮钮可见时必须避开输入区，不能挡住停止按钮。

包内保护专项为 `ops/desktop/rag-protection-smoke.mjs`，同样由当前候选包内 Node 执行，参数为当前与上一候选包的解压 EXE 路径。实际服务与归档函数全部来自包内，检查首次收据、受理失败、在线归档拒绝、V2 快照与旧包拒绝、恢复去重，以及未来数据库的拒绝和字节不变。

本轮复验发现端口监听可能早于网页初始化失败。Windows worker 现在确认实际工作台入口可用后才通知启动成功；非正常响应会明确停止启动，不为未来数据库单独复制一套校验规则。

专项使用真实 SQLite／JSON、合成资料、本机模型替身；实际 HTTP 检查使用生产 Next 服务与本机真实 MCP，复跑入口为 `node ops/verify-rag-tasks.mjs`，需先完成生产构建。
