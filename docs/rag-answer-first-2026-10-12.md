# 同一次回答判断缺口与按原文补查

## 当前实现

实验开关开启且工具能力已核实时，正式问答入口使用 AI SDK 的生成调用：在同一次输出中给出回答或具体缺口。有足够依据就直接使用回答，不再额外调用一次最终模型；需要补查才进入既有 SDK 只读工具循环，结束后另行生成最终答案。明确日期范围已读完、字面查找及未知工具能力仍沿用普通路径。没有增加独立路由模型或必经 Jev。

首轮返回的 JSON 在服务端检查结构、完整结束和长度，再发布回答；取证文本、缺口判断和工具消息不写入用户正文或历史。历史同时提供给首轮和工具阶段。来源编号、版本变化、日期/字面约束、取消、两轮决策、八次 MCP 和 120 秒限制保持。首轮回答需完整缓冲后才发送 delta，并非逐 token 展示。

MCP 分页结果增加可选 `rangeSection`：只有整段落在同一 H3 小节内才提供所属标题和索引。沿用 Markdown 位置解析，忽略围栏内伪标题；跨小节或前言不强行归属。日块 hash、range chunkId 及公开来源身份不变，避免把日版本误当成小节版本。旧服务省略字段仍兼容。

真实模型对照发现强制工具调用在 DeepSeek 思考模式返回 400；[官方接口](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/)确认不支持 `required`。改为 `auto`，参数校验和工具资格保持。取证阶段只返回文本时结束补查、标记受限并另外生成最终回答，不转发内部文本或声称范围已读全。鉴权、限流和网络错误仍作为错误处理，不自动改为不支持工具。

## 对照结果及限制

全部使用冻结的四个月完整合成文件，未删掉其他规则制造收益。模型始终是 DeepSeek Flash，同组普通 RAG/Agent 使用相同思考设置。原始正文、题目、回答、引用、用量和哈希在忽略目录留存。

- 关闭思考的 28 个回答完成，共 63 次上游调用；三种归档问法有四次正确补查，但另两次跳过了缺失的规则关联；两次长排错都错误套用相似规则。不能因调用下降就算通过。目录 `.local/rag-section-entry-1791773376927/`。
- 低强度思考、修正工具兼容后的四组 16 个回答完成，共 50 次调用。归档两次均沿原文找出三项条件及否定；长排错两次均找到正确的另一篇检查说明、没有额外批准要求。普通 RAG 在这四次只读到未给出规则名称的片段，无法提供完整条件。Agent 归档约 39–44 秒/7 次调用，排错约 72–84 秒/8 次调用。短读书对照两边均一次调用；指定两日比较两边均三次调用且不进入 Agent。目录 `.local/rag-auto-low-entry-1791774061299/`。
- 第三种归档问法另做两次重复，两次 Agent 均正确补齐规则关系及条件，7 次调用、约 45 秒；两次普通 RAG 均正确说明缺少关联依据。目录 `.local/rag-low-phrasing3-1791774862233/`。
- 第一种问法补验只完成一对，Agent 正确补查；第二次尚未完成时为纠正聚合预算核对主动停止，不计两次重复通过。启动额度漏计部分未知用量预留，停止时尚在追加 10 元内；账本保留每次启动预留，不能仅用较早的 report 快照统计。目录 `.local/rag-auto-low-rest-1791774614809/`。

以上证明主后端在两类材料上出现可重复的补查收益，也证明语义判断受模型设置影响，不能把关闭思考的错误当成已解决。指定范围比较的部分摘要仍夹入“未提供另一日记录”等不属于原日志的材料覆盖判断；两条路径均受影响，这是下一项实际缺陷。短读书回答还出现原文未给出的性别代词。三种问法的完整重复、短排错新设置对照及摘要忠实性仍需补齐。默认 Agent/Jev 保持关闭，整体目标未完成，不推出新的组件补丁掩盖这些问题。
