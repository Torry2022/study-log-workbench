# 侧栏、悬浮滚动条与返回顶部修正

## 已确认问题

- 日志页右侧工具栏样式在 1181–1279 CSS 像素范围仍固定左栏 260px，其他模块为 220px；相同窗口切换模块时左边界发生变化。
- 先前的 `scrollbar-gutter: stable` 只保持布局宽度稳定，仍预留滚动条空间；日志侧栏和日期列表嵌套后出现额外右侧留白，不符合桌面端悬浮滚动条要求。
- 公开版没有迁移个人版返回顶部的控件及行为，仅残留了相关选择器。

## 实现范围

日志与其他模块沿用同一侧栏断点。220px 侧栏内保留“新建”文字，收起旁边的加号，避免日期输入框文字裁切。

公开版网页通过 `public/scrollbars/overlay-scrollbars.js/css` 加入独立覆盖层，浏览器与 Windows 内嵌页面加载同一份资源。桌面设置窗口只引用同一份文件，不维护第二套滚动实现。保留原有滚动容器、滚轮和触摸滚动，不插入内容包装层；垂直／水平手柄直接驱动原容器，支持拖动、键盘及滚轮，不占布局宽度。滚动、内容变更、尺寸变化和图片／字体加载更新手柄，遮挡区域不显示可点击手柄。颜色沿用现有主题变量。原生开关曾实测不生效，最终实现不依赖这些开关，也没有修改系统设置。

`BackToTop` 复用个人版 48px 控件、箭头与进度环样式，滚动超过 8px 出现、停滚 2.5 秒隐藏，悬停或聚焦时保留。只处理当前模块的可见阅读区域；统计页独立滚动区、日志源码和分屏预览分别定位，隐藏的编辑器不参与其他模块回顶。避让右侧工具栏和手机底部导航，遵循减少动态效果偏好。

侧栏、滚动与返回顶部均以网页源码为唯一实现。本地桌面包随构建带入网页；连接服务器时以服务器提供的网页为准，不在桌面层强行改写远端主界面。

## 验证记录

- Web 类型检查和生产构建。
- 独立 Playwright：五模块、日夜主题、1180／1230／1280／1600／420 窗口宽度，检查侧栏统一、滚动及弹窗锁滚前后坐标、根与嵌套滚动区实际预留宽度为零，横纵手柄实际拖动。
- 模型设置、日志历史版本、使用方式窗口的内部滚动，日志历史及生成方案弹层。
- 五模块窗口回顶、停滚隐藏／继续滚动唤出，源码回顶及普通浏览器统计独立滚动区回顶。

类型检查和生产构建通过。最终共享实现的针对性检查通过，证据 `.local/app-scrollbar-1791531674874/report.json`：Electron 1230px 两种主题、五模块、三个桌面设置窗口、横纵手柄拖动、长日志保存、弹层及回顶；普通 Chromium 的五模块共享资源、侧栏和回顶，以及统计独立滚动区。人工查看输出截图确认日期完整显示、左右侧栏没有滚动预留空隙。

最终完整脚本也通过：`.local/app-scrollbar-1791531728608/report.json`，Electron 五宽度 × 两主题 × 五模块共 50 组，加上述桌面设置、编辑和普通 Chromium 检查。几何检查同时覆盖无滚动、出现滚动和弹窗锁滚状态，根与嵌套区域实际预留宽度为 0。使用隔离合成数据；未验证新安装产物，也未操作日常学习记录。

浏览器回顶检查曾发现平滑滚动停在 4px，修正按钮接近顶部时提前禁用造成的中断，最终仍按精确回到 0 验收，没有放宽断言。早期 50 组桌面宽窄屏检查 `.local/app-scrollbar-1791530626392/report.json` 通过，但当时为桌面注入方案，不能冒充最终共享实现的全部证据。本轮没有推送、发布或覆盖日常安装。
