# 实例运行与维护互斥

正式 Web 启动入口 `ops/run-web.mjs` 与 standalone 的 `ops/serve.mjs` 在整个服务生命周期持有 `data/.instance-operation.lock`。初始化及维护使用相同锁，运行期间不能再次初始化、启动第二个 Web 进程或执行离线维护。只读检索服务不写原始资料；进行维护前仍应停止所有关联服务及外部编辑器。

锁的 `owner.json` 记录随机归属、操作名、进程号和开始时间，不含配置凭据。只释放当前进程建立且归属未变的锁；不会凭时间或 PID 自动清理遗留锁。

服务子进程正常退出后才释放锁。进程无法启动时释放已建立的锁；异常退出或强制终止保留锁，避免把可能未完成的操作当作正常停机。在 Linux 上，SIGTERM 转发给服务并等待其正常退出。Windows 的进程终止可能是强制结束，不能视作优雅停机。

遇到遗留锁时，先确认同一实例的 Web、检索进程和外部资料编辑均已停止，保留完整实例副本，核对有无随记恢复标记或未完成写入。确认状态后将锁目录移到副本中留作记录，再启动；不提供自动解锁或按进程号直接删锁的命令。记录的 PID 可能已经被系统复用。

当前初始化/子进程/锁归属测试已在 Windows 和隔离 Linux Node 22 容器执行；Linux 包括 SIGTERM 后等待异步收尾。真实问答长流停机、离线归档及完整 Compose 安装随对应批次继续验收，这些结果不代表已支持在线热备份。
