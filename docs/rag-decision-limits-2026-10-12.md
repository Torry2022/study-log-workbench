# 内部取证输出达到上限

后续已取消工具决策独立的 1200 tokens 设置，继承模型默认输出限制；本页描述的是 length 的处理，不把较早设置视为合理标准。见[后续修正](rag-tool-output-default-2026-10-12.md)。

取证工具循环的输出不是用户最终回答。内部模型以 `length` 结束时，现在停止补查，设置 `limited` 和 `decision_output_limit`，再由独立的最终回答阶段只使用已保留的证据。不能把被截断的内部文字、推理或工具参数当成完整结果，也不能据此把范围标为读完。没有提高取证输出额度或增加补查轮数。

首轮回答/缺口 JSON 和最终用户回答仍拒绝不完整输出；鉴权、限流、网络错误、内容过滤仍按错误处理，不转成“不支持工具”。取消、两轮工具决策、累计八次 MCP 及整轮 120 秒边界保持。

验收代理的请求限制调整为 256000 UTF-8 字节，适配已有中文证据、历史和来源元数据。材料不被代理截短；调用次数限制、按实际请求字节计算的启动预留、取消传播、未知用量保留与无自动重试规则保持。这只影响隔离模型验收，不改变产品额度或扩大测试授权。

164 项 RAG 检查、7 项预算代理检查、类型检查和生产构建通过。正式入口新增内部输出上限检查，连同原三组接口和 Chromium/WebKit 浅深色检查共八项通过：内部消息不发布，原来源保留，受限信息传给最终回答，完整结果才发送 done。相关报告在 `.local/rag-entry-production-1791780907808/`。没有将用户资料或由其生成的问题、回答、来源及评估内容纳入源码。
