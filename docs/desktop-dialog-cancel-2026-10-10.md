# 桌面弹窗取消路径修正

用户反馈“日志历史版本”设置窗口点击取消后主界面闪一下，原生右上角关闭没有该现象。本批保留历史版本启用开关及保留期限，只调整取消窗口的路径。

## 核查与修正

检查桌面全部四个 HTML 页面：标题栏不自行关闭窗口；模型设置、日志历史版本设置、使用方式的取消按钮原来都调用渲染进程 `window.close()`。备份、恢复、文件选择、更新、关于和错误提示由 Electron 原生对话框提供；网页模块弹层在共享 Web 内部管理，没有发现同样的 `window.close()` 路径。

修正前隔离 Electron 事件探针显示：历史设置按钮取消产生 WebContents 的 `close`／`destroyed`，未进入 BrowserWindow 的 `close` 处理；主进程原生关闭则先进入该处理，执行隐藏窗口后销毁。此前只检查主页面没有重载，不能覆盖这个关闭路径差异。

三个窗口的 preload 仅暴露取消请求，主进程核对当前窗口、顶层 frame 和准确页面地址后调用该窗口的 `BrowserWindow.close()`。按钮与原生关闭因此共用既有收尾逻辑。模型／历史设置继续在销毁前隐藏，再将焦点交还工作台；使用方式在已有工作台时取消保持原连接，首次进入时取消正常退出，不创建学习记录。不改变保存设置、连接提交、未保存保护或历史版本策略。

## 验证

`node ops/electron/settings-boundaries-smoke.mjs` 在临时合成目录运行源码 Electron。最终证据为 `.local/settings-boundaries-1791635478557/report.json`：

- 三个窗口的鼠标取消、Enter 取消及主进程原生关闭，均经过各自既有原生关闭事件；窗口不泄漏或重新创建。
- 反复打开／关闭后，未保存日志草稿、配置、桌面偏好和服务运行身份均保持不变；主窗口没有隐藏、销毁或页面重载。
- 首次使用三种取消路径均正常退出，没有创建记录目录或桌面偏好。
- 模型／历史设置的未修改不可保存、无变化 IPC 不关闭窗口、读取失败保护、输入校验及浅深色／窄窗口检查继续通过。

`node ops/electron/settings-smoke.mjs` 另行通过实际模型设置保存／重开、Key 不回显、备份取消保留草稿、历史预览及单日恢复、完整归档、新目录恢复及原目录保留流程，证据为 `.local/desktop-settings-1791635717849/report.json`。
