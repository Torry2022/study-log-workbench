# 读取失败与问答连接恢复

公共 JSON 请求层负责读取恢复，两版网页与鸿蒙采用相同边界；页面控制器仍负责选择、草稿和请求结果归属。

- 明确的业务读取 GET 最多两次，每次最长 10 秒，间隔 350ms；总预算约 20.35 秒。不叠加日志或问答专用重试。
- 502/503/504 和可识别的暂态传输错误可重试。401/403、404、409、429、实例切换、取消与响应格式错误不重试。鸿蒙证书校验失败不重试；浏览器 fetch 无法细分 TLS 原因，最多按原安全策略重试一次，不改变证书校验。
- POST/PUT/PATCH/DELETE、文件上传、模型生成不使用读取重试。任务协议原有的提交身份恢复继续由任务客户端管理，不能用新身份重复生成。
- HTTP 成功但 JSON 无法解析时明确报告响应格式异常，不再用空对象继续执行。诊断仅记录接口类别、状态码/原生错误码和尝试次数，不记录查询参数、正文或凭据。
- 问答无活动任务时每 15 秒对账；活跃任务以 1 秒轮询兜底，收到有效实时事件时降到 3 秒。持续故障按 2/4/8/15 秒退避，后台暂停观察，回到前台立即对账。浏览器恢复在线也立即核对。订阅关闭不取消服务端生成。
- 两次读取仍失败时保留明确错误；只有成功读取后清除。历史数据与草稿保留，恢复入口继续可用。问答流每 10 秒发送注释心跳，不能把心跳当成回答或任务进度。

验收使用合成资料和故障注入。`study-log-web/scripts/read-recovery.test.mjs` 覆盖瞬断、持续失败、取消、鉴权、格式、时间预算与写入次数；`task-discovery-recovery.test.mjs` 覆盖空闲/实时/故障调度及前后台恢复。鸿蒙同名测试执行实际 ArkTS 控制器与传输源码，另需 release 编译。

生产构建后，可在网页目录运行 `node scripts/verify-read-recovery-browser.mjs`。脚本创建独立临时资料、启动本机服务，在 Chromium/WebKit 验证统计及问答真实页面的失败和恢复，不调用外部模型，不使用已有工作区。可用 `READ_RECOVERY_OUTPUT` 指定证据目录；故障注入只替换本机浏览器读取响应。该检查不能代替安装后的真机验收。
