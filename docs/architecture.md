# 架构

`study-log-web/app` 使用 Next.js App Router 提供 `/study-log` 入口。根布局在首次绘制前初始化主题；基础CSS注册三个本地字体族，原始字体与许可证作为静态资源提供。

认证API使用实例密码校验和HMAC签名；Cookie与App Token按受众区分。能力接口读取实例身份、聊天配置及模板状态，不产生资料写入。日志读写、整理、AI 写作与日志问答已接入；各自的验收边界见[实施状态](implementation-status.md)。

`AuthGate`负责认证生命周期，`LoginScreen`仅持有密码、提交中和错误状态。认证过期保留工作区组件实例并隐藏内容；重新认证后恢复，主动退出则卸载清理。共享JSON请求在会话变化时取消，并在解析响应后检查取消状态，避免不遵守取消的旧响应回灌。业务模块从会话上下文读取活动状态，并分别验证草稿与流的生命周期。

`ops/instance.mjs` 负责实例初始化。它只操作显式传入的绝对目录，识别已有身份，使用独占创建保留原配置。`ops/run-web.mjs`读取选定实例环境，强制数据根为该实例的data目录；它与standalone入口`ops/serve.mjs`共用服务监督器，持有含随机归属的运行锁直到子进程正常退出。异常停止保留锁，维护只释放自己拥有的锁。Linux真实SIGTERM及子进程异步收尾测试通过；问答长流和完整部署停机仍待对应批次验证，见[维护边界](maintenance.md)。

## 数据边界

MCP 的只读基础由 `paths` 验证显式且不重叠的 `LOG_ROOT` / `INDEX_ROOT`，`markdown-source` 按 AST 根标题解析真实年月文件，`log-store` 提供日期与来源读取。`KeywordRetriever` 保留 BM25F、同小节合并、重复内容过滤、字面匹配和三种上下文排序；纯关键词路径不联网、不创建索引，不读取随记、Wiki或附件正文。`HybridRetriever` 可叠加独立配置的向量和重排；故障回退第一阶段结果并说明诊断。缓存身份核验持久实例UUID、路径、端点哈希、模型、维度及切片版本，进程内串行、完整临时文件原子替换，失败保留旧缓存。只读 MCP 协议和 Web 问答已接入；真实向量及重排提供方尚未验收。

只读链为API鉴权→参数及源文件校验→Markdown根级标题解析→日块/目录结果。`day-content`使用Markdown AST处理围栏和嵌套内容，日期及小节共享同一种根标题语义；`log-store`管理文件枚举、按内容校验的解析缓存和版本快照。只读方法不创建资料，错误处理保留可操作的结构错误并隐藏底层文件系统细节。

源码仓仅保存代码、公开资源与合成测试；用户资料和配置属于显式指定的实例目录；索引是可重建数据，备份是独立恢复资料。后续实现不得依赖源码父目录寻找资料。

附件只读入口经合成目录测试验证根目录/子级链接隔离及打开期间目录替换，Windows文件符号链接测试因系统权限跳过；目录联接场景已实际执行。部署目标Linux的链接测试仍须在部署批次执行。该检查不把拥有实例目录写权限的本机用户视为可信隔离沙箱。

## 阅读目录语义

分类建议的 `useTaxonomySuggestions` 只管理请求和待审核建议，`useStats` 继续持有唯一分类草稿。请求只基于已保存领域；手工编辑会取消旧请求并作废旧建议。应用前再次读取保存版本进行比较，不以新快照覆盖用户草稿；审核选中的建议只合并入草稿，后续保存仍由现有版本化分类接口处理。

普通搜索直接读取权威日块，按字面逐行匹配；标题范围复用AST根级H3语义，不依赖派生检索索引。搜索框维护查询、取消与键盘选中，父工作区负责草稿保护和选中后的高亮定位；搜索历史最多8项，显式退出清空，过期重登保留。手机与桌面复用同一个搜索组件，避免隐藏组件发请求或争夺焦点。

正文目录复用日块解析器的Markdown AST根级标题结果（H2–H6），不再另行切换围栏布尔值；围栏字符/长度、列表嵌套和引用均由同一语法树处理。目录保留行号，并对重复标题生成稳定的递增锚点。

## 客户端职责

`useRag` 管理流式回答与版本化会话保存，`RagWorkspace` 负责正文、引用及新回答自动跟随，`RagHistorySidebar` 负责历史筛选、弹层和内部列表滚动。`useLogWorkspace` 维护 `view=qa` 与会话 URL；根工作区统一处理离开确认及引用跳转。移动抽屉的实际可见状态传给历史组件，隐藏时不创建弹层、争夺焦点或滚动当前会话。

RAG 的检索规划、MCP 边界校验、回答流解析和历史存储分别独立。服务端只在提供方完整结束后发 `done`；客户端再次核验结束事件和来源结构，EOF 不代表成功。历史请求保存稳定操作身份与会话版本，未知结果不会清稿。自动标题不能覆盖手动标题，也不能用迟到响应偷偷推进另一个对话快照的版本。

`useWriting` 管理材料、补充要求、生成稿和请求代次；右侧栏折叠保留内容，日期/认证/模块变化中止旧请求。根工作区在确认离开后统一丢弃日志及 AI 草稿，单独“放弃日志修改”不影响材料。应用生成稿前再次核验日期和编辑状态，只追加到编辑器，复用现有保存事务。`WorkspaceChrome` 只控制侧栏宽度和手机抽屉；工具栏依据阅读容器宽度布局。

材料解析与模型请求分离：`upload-extract` 只解析有界文本，不保存上传原件；`ai-generation` 组合实例模板、有限的当日日志与近期标题；`ai-chat` 负责超时、取消、响应大小和安全错误。生成结果经 Markdown AST 验证，不能引入其他日块或吞掉相邻日块的未闭合根围栏。模板负责写作偏好，存储层继续负责文件结构；不内置个人 Skill 或固定写作风格。

`highlight-ranges` 从 Markdown AST 的可标注文本提取原始偏移和 token 身份，模型只能选择范围，服务端只插入粗体标记并核验实际解析结果。`useHighlighting` 保留请求时的日期与原文；审阅对话框应用前和根工作区写稿前各核验一次快照。关闭、认证失效或模块变化只取消审阅，不改源文；应用结果继续使用日志编辑器的显式保存。

`useNotes` 维护随记列表、筛选和编辑基线；正文、心得、来源与标签分别保存。提交时复制稿件，响应只推进该次保存的基线，期间新输入保留为未保存修改。图片插入记录字段和选区，输入时映射位置；取消、放弃、认证变化后迟到上传不能进入新稿。随记读取与保存取消相互协调，旧列表不能覆盖成功写入。来源往返保留仍适用的筛选，指定随记深链在必要时清筛选并展开定位。

`useExport` 只下载已保存资料；未保存稿先明确确认，下载不改变编辑状态。Blob 读取与 JSON 请求共用认证代次，日期、模块、认证变化或显式取消均中止迟到下载。`ExportMenu` 提供桌面菜单及手机操作项，根工作区呈现进度和可重试错误。四类内容导出按原文件组织附件，不等同于包含配置、收藏和历史的整实例备份。

统计由 `stats-store` 从权威日志计算，根级 H3 及真实日块决定计数；只有“其他”是内置领域。`taxonomy-store` 的完整快照版本保护用户自定义映射，写前唯一备份，临时文件替换。`useStats` 分开管理月度读取和分类草稿，迟到月份请求不能替换当前月；409、读取失败和认证过期不覆盖未保存映射。图表钻取传回日期和实际标题序号，由工作区核验后定位原文。

收藏记录独立于原日志，保留日期和H3标题身份；来源失效只改变解析状态，不删除收藏。元数据写入与快照读取共用实例内队列，避免Windows读取与rename冲突。一个`useFavorites`管理目录星标、中心和侧栏的共享状态，成功写入先更新本地快照再刷新；刷新失败仍保留写入结果。导航选择包含当前模块，切模块及历史返回复用草稿保护。隐藏日志阅读器保留编辑实例，但停止滚动定位、尺寸测量和快捷键，避免影响当前模块。

`WorkspaceChrome`只负责导航壳与响应式控件；`useLogWorkspace`持有月份、日期、取消和URL状态；`LogReader`负责阅读定位和目录；`MarkdownPreview`统一渲染正文及后续问答。读取期间导航列表仍可切换，迟到响应不能回灌。浏览器历史保存来源滚动位置，内部链接使用稳定标题ID或原文标题定位。会话过期隐藏的业务树在重登后重新读取。

## 编辑与版本事务

加载、空白和读取失败共用 `components/WorkspaceState.tsx`，包括认证、日志预览/源码、随记、收藏、统计和问答。调用方提供状态、内容及重试操作，既有容器样式决定位置：日志加载仍在正文起点左对齐、旋转图标位于文案右侧，模块空态使用内容区居中规则；不把所有场景强制改成同一坐标。

`useNoteCandidates` 在根工作区常驻，负责材料选择、顺序解析、提取结果和待确认的批量保存快照。提取结果使用服务端 UUID，新增标签须人工确认；保存开始后锁定原批次，未知结果及认证中断不改变身份或内容，只有核对返回记录后才清稿。`createStudyNotes` 在现有随记队列中核对 UUID 和规范化业务字段，重复请求复用原记录，新增记录统一进入现有年度写入流程。候选界面负责审核，不能直接修改分类或自动写入日志。

`LogEditor`持有同一日期的CodeMirror实例与撤销历史；`useLogDraft`管理正文、已保存正文、版本及保存状态；`useLogWorkspace`负责导航和读取，列表刷新与正文重新读取分开。保存响应仅更新提交时的基线，保存期间的新输入仍是未保存草稿。离开确认置于业务导航边界，浏览器后退取消后恢复已接受的历史位置。

重复选择当前月份是幂等操作，保留当前日期、标题定位和未保存草稿，不依赖重新请求日期列表来恢复选择。收藏目标缺失以独立的可空状态记录，离开对应日期后清除，不能把空日期当成缺失收藏。

日历和侧栏等待日期导航的接受结果，再关闭浮层并清除筛选；取消离开时保留原上下文。离开确认拥有最上层的键盘焦点和 Escape，底层日历、手机抽屉不提前消费该操作。

普通日志日期跳转先保存来源滚动位置，再在加载开始前回到页面顶部。这样加载态与完成态的工具栏边线处于同一坐标；指定小节跳转及浏览器历史仍由阅读器在目标就绪后定位。

`useReadingPosition`在布局切换前捕获源码偏移，切换后对应Markdown渲染块或编辑器行恢复；无法映射时才按滚动比例回退。它不持续监听滚动，不引入双向滚动同步。正文内部链接回调保持稳定，目录高亮更新不会使Markdown组件重建。

写入在实例内串行，`baseVersion`必须明确传入，null只表示目标日不存在；字符串比较完整源文件快照。`log-store`决定年/月归属并保留其他日块字节，替换前创建唯一完整文件备份，再以同目录临时文件rename提交。备份根由实例启动器明确指定；错误不回传本机路径。追加、删除及日块恢复共用此事务，不直接复制整月备份覆盖当前资料。

`useEditorAttachments`保留上传时的文档与插入选区，通过CodeMirror变化映射原位置；日块、会话、模式或显式草稿重置变化取消操作。图片成功后作为一个可独立撤销的编辑事务插入，不自动保存。服务端先验证整批元数据和体积，再生成唯一附件名，失败仅回收本次创建且身份可确认的文件。

普通内部链接使用原始日志作为来源。选择器负责搜索、别名和键盘交互；阅读器负责目标存在检查、编号标题匹配及来源位置恢复；它不依赖Wiki。链接弹层挂到文档根，避免阅读器容器限制手机窗口宽度。

`day-backup-store`负责历史版本枚举、日块去重和预览；恢复同时检查历史摘要与当前源版本，并交回`log-store`写事务。`BackupDialog`持有预览/请求状态，父工作区确认稿件丢弃并在成功后接收新日块。弹窗的滚动锁与背景inert按使用次数释放，保证嵌套弹窗在认证失效时任意卸载顺序都能还原页面。

## 鸿蒙客户端当前边界

公开鸿蒙端使用连接时选择的实例 origin 与 App Token；`ApiClient` 在响应返回前核对实例和会话代次。日志阅读、版本写入、附件上传、内部链接、搜索与导出均使用公开 Web/API 契约。`LogsReaderPage` 持有当前日块、源码草稿和导航状态；离开前通过同一编辑器快照检查未保存修改。ArkWeb 阅读页带令牌请求当前实例图片，附件 GET/OPTIONS 支持跨源预检但 GET 仍要求认证；点击已加载图片交由原版图片预览组件显示。统计、收藏与随记沿用个人版页面和导航组件，分别适配公开 `/stats`、`/favorites`、`/notes` 契约；随记编辑由 `NoteEditorSession` 保存基线，模块切换检查未保存状态。窄屏沿用原版顶栏和底部模块导航，当前模块的导航内容装入侧层；搜索历史复用原版列表组件，按公开实例命名空间保存在设备本地；本机阅读与编辑偏好由 `WorkspacePreferences` 保存。

日志 AI 生成与重点标注使用公开实例服务，在日期及编辑器快照核对后仅修改未保存草稿。随记候选保留原版审阅界面，但先经 `/materials/extract` 逐份解析，再向 `/notes/candidates` 发送材料 JSON。问答页面沿用原版结构，`ApiClient` 提供可取消的实例隔离 SSE；会话控制器只有收到 `done` 才视为完整，历史写入携带版本和稳定操作 ID，未知结果重试不重复调用模型。真实模型、材料文件选择、历史与引用的设备闭环尚未完成；`study-log-harmony` 的构建及纯逻辑测试不替代多端和独立安装验收。
