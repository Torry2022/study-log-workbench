# 按需问答实施记录

本项从 2026-10-15 开始，目标包括直接回答、必要补查，以及真正超出输入容量时的分批处理。没有额外引入每题一次的入口判断模型，也没有将固定分页改名为 Agent。以下是本地实现与实验记录，不是发布记录或整体质量验收结论。

## 当前实现

- 首个 SDK 调用只在 `reply`、`read_more` 和 `search` 中选择。直接答复经过参数、来源身份和原文锚点检查后交付；`read_more` 只能读取已登记来源的未提供正文，`search` 用于仍未命中的具体线索。补查后才提供 `assess`，保留实质材料判断，正文单独生成。
- `agent.enabled` 表示允许使用工具；`agent.entered` 表示实际执行补查或分批处理，不能用前者冒充后者。没有额外入口分类模型，也不把首步直接答复记作进入 Agent。
- `planRagMaterial` 统一容量计算，并完整规划原文分片。新工作材料路径不改写原文、哈希或读取覆盖；仅保留已提供片段中的逐字摘录。原文已读完与模型尚未处理完分别记录。
- 工作摘录增量提交，旧内容由代码保留、去重，模型按编号移除不再需要的部分。超出工作记忆时返回容量反馈，保留已接受状态；调整与复看共享最多四次材料步骤，不扩大两步补查、八次 MCP 或整轮 120 秒边界。截断、非法参数和不可核对摘录立即取消，不等待或继续失败流。
- 只有明确声明上下文窗口、且原文确实超过该输入预算时，才进入新分批路径。未知窗口的 30,000 字符兼容上限不证明模型原生上下文不足，仍使用兼容 RAG。
- 总开关未设置或为 true 时允许按需运行，false 明确关闭；工具能力仍须显式确认。新实例默认允许按需运行、能力未确认。已有实例不自动改写，也不按供应商名称启用。Jev、范围末状态核对仍独立且默认关闭。

## 真实材料对照

全部使用已授权的隔离日志副本。私有问题、历史、摘录、模型响应和凭据均不进入 Git。

同一冻结输入、同一模型与参数的首轮交替对照包含两类充分材料、两类必要补读，各重复两次：旧路径共 22 次调用，候选共 17 次；总耗时中位数约 15.0 秒和 10.4 秒。充分材料候选四次均未补读，其中三次直接交付、一次仍先提交判断；必要补读四次均读取了相关原文。这不证明所有问题都能提速或引用无误。

其他会话复核中仍有收益不明的补读。部分宽泛问题沿用判断后交付，不能宣称额外生成已全部消除。扩展组与另两条材料复核有短暂并行，耗时不作为严格比较结论。

随后通过实际问答编排、本机 MCP 和真实模型回放原有八个会话的十五轮问题：十五轮均结束为 done，共 35 次模型请求，单轮 1～4 次，五轮直接交付，四轮实际补查；总耗时中位数约 9.7 秒，首次可见正文中位数约 7.3 秒，最长约 21.7 秒。此轮声明 1M 窗口，材料没有触发分批；回放通过不等于十五条回答全部语义达标。仍可见多余缺口说明、通用知识位置及收益不明的读取。

## 长材料实测及取舍

另取同一实际十四日范围、49,568 字符，检查兼容输入预算下的材料处理。它没有超过实际模型的 1M 窗口，不能称为原生超上下文实验。

1. 旧兼容摘录加正文共两次请求，约 11.9 秒。
2. 初版每步重写全部工作摘录：第三步触及供应商 8,193 输出 token 上限，并曾启动一个随后被取消的请求。没有正文交付，未采用该协议。
3. 增量摘录版不再重写旧内容，但第二批工作记忆超限，按当时规则停止；保留该失败，没有将其计作成功。
4. 加入同预算容量反馈后，共五次请求、约 44.5 秒，仅处理四批中的两批，再按部分材料回答。它证明限制和未处理状态能够保留，没有证明完整总结或速度收益。
5. 原文直接提供给声明 1M 窗口的模型，仅一次请求、约 7.2 秒。材料能容纳时直接生成，因此正式路由不以未知窗口的兼容字符上限强行进入分批。

真实原生超窗材料的完整覆盖、事实保留与成本收益尚未验证；当前 MCP 原文保留上限也限制了可构造的自然溢出范围。不得删材料、缩小已知模型窗口后宣称证明收益。新路径具备有界执行和隔离工作材料的实现，质量仍是未完成事项。

## 2026-10-16 首步协议收口

首步不再提供 `assess/finish`。材料足够就由 `reply` 一次交付；已命中来源但缺少回答必需的正文才使用 `read_more`；未命中线索才使用 `search`。这让“直接回答”与“实际进入 Agent 补查”成为互斥结果，没有增加一次入口判断调用。对于是否存在、是否做过一类问题，一条直接且充分的原文已经可以支持肯定回答；用户没有要求列全时，不为增加例子补读。`reply` 和 `assess` 主动提交的每条摘录分别核对对应来源，不能再由同一批中的一条真实摘录掩盖另一条失真摘录；这项检查不证明答复全文语义正确。

官方 DeepSeek Flash 在显式关闭思考时实际请求确认支持强制工具选择，随后仅在这个已核实组合中使用 `required`。Pro 虽允许配置关闭思考，但没有同等工具能力证据；开启思考和其他兼容模型的能力也不能由设置或模型名推断，因此仍用 `auto`。自动模式下模型若输出普通文本而未调用工具，服务端丢弃这段内部文本并沿用普通回答路径，不再返回协议错误，也不把未检查内容写入会话。

使用隔离的线上日志副本和冻结的五个真实会话问题重放：三题由 `reply` 一次完成，`agent.entered=false`；两题分别在读取两个已命中日期后完成判断与正文生成，`agent.entered=true`。五题均收到 `done`，耗时约 5.4～17.7 秒，没有一分钟级等待。此前相同代码阶段使用 `auto` 时有两题直接输出普通文本并报协议错误；另一个问题读取四个日期，本次在明确“存在性问题不为增加例子补读”后读取两个日期。该结果证明入口与执行状态已经分开，不证明模型对所有问题都会选择最少读取。

## 验证与剩余工作

专项测试覆盖直接交付、异常参数、失败及取消、原文不可变、来源身份、连续分片、UTF-8 边界、末尾内容、工作记忆反馈、增量新来源与未处理批次。旧兼容摘录测试发现测试 HTTP 服务逐块直接转字符串，已改用 UTF-8 流解码，保留原断言。

按需入口的结构目标已完成：简单问题可直接交付，需要动态取证时才进入有限工具循环；显式容量超限时进入独立分批路径。长材料在同一执行预算内的完整处理仍没有实际收益依据，回答与引用的语义正确性也继续属于模型质量评估，不能由这次协议通过代替。

最终本地验证：问答专项及通用主题共 306 项通过；Web 全量 547 项通过、3 项原权限跳过；MCP 60 项通过、1 项原 Windows 权限跳过；实例与运维 44 项通过、1 项平台跳过；类型检查和生产构建通过。实际生产入口 23 组通过，包含单次直接交付、日期／版本／用量错误，以及 Chromium、WebKit 浅深色桌面和手机；已查看 Chromium 浅色桌面与 WebKit 深色手机结果。没有设备安装、推送或发布。
