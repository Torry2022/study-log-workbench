# Windows 桌面试用版

此入口使用 Electron 承载现有网页工作台，日志与随记的存储格式不变。安装后从快捷方式打开；无需另开浏览器或手动启动服务。首轮为本地试用候选，尚未替换此前 ZIP 包或对外发布。

## 使用

- 首次运行在当前 Windows 用户的应用数据目录中建立独立实例，以后自动打开上次使用的资料。
- 菜单“文件 → 打开资料所在文件夹”可查看存储位置；“打开已有资料…”可选择此前本地包创建的完整实例目录。不能选择只有 Markdown 的普通文件夹作为实例。
- 本机应用使用现有认证接口自动登录，不要求输入服务密码。自动登录依据当前 Windows 用户对资料配置的访问权限，不是独立的本地应用锁，也不关闭 HTTP 接口认证。服务仅监听本机。
- 关闭窗口或选择“退出”时，有未保存内容会询问是否离开。确认后等待所属服务完成停止；重复打开会激活已有窗口，不启动另一组服务。
- 菜单“文件 → 模型设置…”可填写模型接口、名称和 Key，留空 Key 保留原值，也可明确清除。保存会重新打开工作台，未保存内容仍需确认。未配置模型仍可写记录。
- “备份全部资料…”正常停止服务后创建 `.slarchive` 归档和校验文件，随后重新打开工作台；“从备份恢复…”先校验归档，再在选定位置新建恢复目录并打开。原资料不会被覆盖。归档包含实例配置和密钥，请妥善保管。日志内的日块备份继续可用。
- 资料位置丢失、实例锁遗留或服务异常时保留错误，不自动删锁、清资料或重新初始化已有实例。不要将异常锁当成可直接删除的临时文件。

## 开发与验收

在 Windows x64 构建，先安装网页与检索服务依赖，执行网页类型检查、生产构建，再运行：

```powershell
npm ci --prefix ops/electron
node ops/electron/node_modules/electron/install.js
npm run package:electron
npm run desktop
npm run test:electron
```

打包复用 `ops/desktop/package-windows.mjs` 的固定 Node 运行时和 Web standalone／检索资源。输出目录必须是新的；已有 `.local\electron-payload` 不会被自动覆盖或删除。安装包输出位于 `.local\electron-dist`，不上传源码仓库。构建失败可在核对已准备资源后单独运行 Electron Builder，无需重新生成同名资料目录。

`STUDY_LOG_DESKTOP_PROFILE` 可为自动验收显式指定独立的绝对路径，使偏好与资料均与日常使用隔离。`ops/electron/smoke.mjs` 默认创建临时合成实例；传入已打包 EXE 绝对路径可对真实包复测。测试不安装到日常目录，不调用付费模型。

窗口保持沙盒、上下文隔离与禁用 Node 集成；网页只得到关闭窗口的最小接口。服务配置和密钥留在主进程／所属服务，不通过桥接接口返回。退出沿用私有 IPC 正常停止，实例锁仅在正常结束后释放。

本轮未安装到系统、未验证安装／卸载／升级流程，安装包尚未签名。系统安装／卸载及更新保留资料仍待验证，不将此候选称为已完成发布验收。
