操作者为本轮实现维护者。这是按使用者文档、从干净源码副本和全新合成实例执行的自行试装；它证明下列实际流程，不伪称由未参与开发的第三方完成。受测提交为 `b128f72`，Windows x64、Node.js 23.8.0、HarmonyOS SDK 6.1.1(24)，手机真机为 OpenHarmony 7.0.0.105。所有实例、截图、签名配置与测试包留在 Git 忽略目录；不包含真实日志、密钥或个人服务地址。

## 从零安装

- `git archive HEAD` 解出 15,073,280 字节的完整源码副本；副本内没有 `.local`、`local.properties` 或签名配置。Web 与鸿蒙目录分别执行 `npm ci`。
- `npm run build` 的 Web 生产构建通过；鸿蒙 `npm run test:protocol` 为 200/200，通过本机 SDK 的 34 项无签名 HAP 构建任务。鸿蒙源码的临时常亮开关保持 `false`。
- 在副本中暂时注入本机已有、匹配公开包名及手机的调试签名，完成签名构建并还原工程配置。签名 HAP 的 SHA-256 为 `5E12EE250EE9A5EA5DAB9822AB934E9646B1097AEC2F4DC2ADE6AFB8BAD233D4`。手机真机覆盖安装两次均成功，安装前的连接状态和已保存日志在更新后仍可读。这是维护者签名试装，不是其他使用者自行配置证书的证据。
- 按 README 初始化全新实例，启动生产 Web；手机连接同一局域网内电脑的临时转发入口，不使用 USB 反向端口。明确启用局域网 HTTP 测试开关后登录成功，强停并重启 App 后自动恢复连接和已保存日志。该临时明文连接只承载随机测试密码与合成资料；尚未验证不同网络下的 HTTPS 反向代理。

## 未覆盖及已知限制

- 手机从 A 实例切换到已准备好的空 B 实例时，真机 HDC 连接中断，未完成手机跨实例隔离；手机图片**剪贴板粘贴**、日志 AI 候选编辑和标注、各尺寸主题与动效组合、前台闲置息屏也未在这次试装中执行。原生文件选择插图不等于图片粘贴。手机 Download 中本次 77 字节合成文件 `study-log-self-trial.png` 尚待设备重连后清理；不要据此删除其他下载文件。
- 网页上传两张图片后，手机显示的是 8×8 像素合成图的放大点，不能据此评价真实照片的展示质量。
- 收藏创建后又改动标题，网页收藏卡仍保存原标题并显示“未找到”；这属于 README 已说明的标题变化后定位 ID 可能失效的限制，本次没有把它算作收藏跨设备同步失败。
- 未调用付费模型；既有 5 元预算已接近用尽。没有执行第三方使用者的独立证书配置、不同网络 HTTPS、跨版本升级或应用市场发布流程。
