# 长材料问答与 Agent 上下文修正

本批延续已有 AI SDK 取证循环，不新增组件。长材料分批整理供普通 RAG 与实验 Agent 共用；Agent 的区别仍是根据证据选择补查、读取或结束，不能把分批摘要本身当作 Agent 收益。

## 修正内容

- 摘要批次同时限制为最多五条证据、正文合计不超过 30000 字符。原来只按条数分批，遇到长片段仍会过大。
- 按来源数量分配摘要长度，使全部整理后正文不超过 30000 字符；保留各来源编号、原文摘录与内容版本。原来固定每条 900 字符，在来源多时仍可能超出总量。
- Agent 不再只接收每条证据开头 1200 字符。进入补查前先整理长材料，每轮使用当前证据、覆盖情况和读取记录重新构造输入，避免反复累积工具正文。各轮工具完成后再整理，避免并行工具同时修改摘要。
- 原始读取量单独累计，压缩后不会恢复读取额度。仍最多保留 160 条来源、读取 120000 字符，沿用八次工具读取、两步补查与整轮 120 秒限制。
- Jev 的短材料适用边界按压缩前的材料判断，不因摘要变短而送入原本超出范围的任务。

30000 是证据正文的字符预算，不是供应商 token 上限；消息元数据、问题和提示词另占空间。超出单片段容量、摘要失败或摘要格式不合格时，保留已有来源并明确标记截断及部分结果。此实现不支持无限上下文，也不能保证摘要保留了所有语义。

## 验证与启用范围

模型替身覆盖大段证据、160 条来源、摘要超长回退和压缩后读取预算。端到端用隔离合成长日志确认末尾“没有确认不能保存”的条件能够经过摘要进入 Agent，并传入最终回答模型。这证明数据流可达，不证明真实模型的摘要质量。

本批没有调用付费模型。Agent 与 Jev 继续保持实验关闭，不变更用户配置，也不发布或覆盖安装。

最终代码通过 137 项问答测试、类型检查及生产构建。Windows 独立服务包通过 Node/Web/MCP 启动、鉴权 SSE、完整模型 URL、SDK 工具循环及 Chromium 宽窄界面流程检查，包括后台标题、来源跳转、历史会话和草稿保留。检查仅使用新建的合成数据目录。

下一步应以相同最终模型比较固定分批整理和自适应补查：问题需要从一条线索继续寻找另一篇记录，且关键条件位于长材料后部。检查是否找齐依据、保留否定与条件、引用是否支持回答，并记录调用次数、耗时和实际费用。只有重复对照显示收益，才考虑启用 Agent。
