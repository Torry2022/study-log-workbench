# 统计分类默认流程修正（2026-10-10）

## 已确认问题

公开版此前只移除了固定技术领域，仍要求使用者先手动创建并保存领域，AI 才能为标题提出映射；空工作台无法直接开始分类。统计主题还沿用去括号的归一化规则，使“读书(历史)”和“读书(心理学)”成为同一个标签，无法分别归类。

## 本批行为

- 未配置模型且没有已有分类时，不提供空的手工领域表，仅说明如何启用；记录天数、小节数量、学习日历和主题频次照常可用。未整理的领域指标显示“—”，不暗示所有内容都属于“其他”。
- 配置模型后，使用者点击“AI 整理分类”，从现有三级标题提出领域及归类；首次无需先建领域。审核时可改变建议领域或取消采纳，应用到草稿后可新增、删除领域及调整映射，再显式保存。
- 后续仅请求筛选范围内的未分类主题。前后端均排除已有映射，包含人工归入“其他”的条目及旧版继承映射；模型不在后台运行，不自动写入。
- 一次最多200个主题、50个一批，优先复用已有领域，各批携带之前提出的领域。最多新增8个领域，名称长度1–40字符；未被有效归类使用或未采纳的新领域不写入草稿。
- 主题保留括号内容，只去掉序号和多余空白。完整标题映射优先，没有单独映射时继续继承旧版去括号键；读取不改写旧文件。用户可分别调整括号主题，原记录不重写。
- Web 与 Windows 继续复用同一界面和服务。鸿蒙同步请求、审核、应用及暂存待审领域；最终保存沿用版本冲突保护、写前备份及原子文件替换。

旧客户端省略请求的 `mode` 时仍使用原来的“只从已保存领域中建议”协议；新客户端使用 `organize`。新增返回字段是兼容性追加，连接旧服务器不会获得建立领域的能力。
