# 跨读取方式的原文版本保护（2026-10-11）

## 问题与修正

此前只比较同一 chunkId 的内容 hash，并由范围分页游标保护连续页。小节搜索与完整日块的块标识不同，先搜索后读原文期间发生修改时，会把新旧正文保留在同一轮。这与按请求管理证据版本的要求不符。

本批 MCP 在小节检索和原文范围读取中增加 `dayContentHash`，都基于完整原始日块计算 SHA-256；既有片段 hash、标题定位与分页 revision 不变。Web 在外部边界校验可选字段类型与长度，证据集合按文件名和日期登记版本，版本比较先于去重。不同标题或小节正文恰好未变也不能跨整日版本拼接。摘要不修改此标识。同一整日版本换词搜索得到不同的合并片段时，其片段 hash 变化并不表示源修改；保留新增片段，不能把这类补查误报为版本冲突。

一旦发现版本变化，当前请求不再发起后续读取；SDK 停止继续取证，查询返回 `MCP_SOURCE_CHANGED`，提示“读取期间日志发生了修改，请重新提问以读取最新内容”。不会把旧材料交给最终回答模型，也不会发布混合引用。没有自动重试、自动覆盖资料或新增模型判断。

该字段只在 MCP→Web 的内部证据中使用，最终来源、来源追问、会话格式和 `status/sources/delta/done/error` 事件不变。旧 MCP 响应省略字段仍能读取；其已有范围片段可从原有日块 hash 登记版本，而旧小节搜索不提供整日版本时仅有原有同块保护，不能宣称获得完整跨方式保护。Web/MCP 需一起更新才能取得本批完整保护。

## 验证

- 147 项问答检查通过，实际 MCP 解析/检索/范围读取覆盖两种读序的改动、新增标题和正文、长日块分页共用版本、同版本去重及保留额外上下文；同一原文换词得到不同合并片段不会误报版本变化。
- 查询入口集成测试在第一次 SDK 工具选择后修改隔离合成日志，实际 MCP 原文读取取得新版本：只有一次工具决策模型请求，终结 error，未发最终回答请求、delta、sources 或 done，没有重试。
- 字段非法类型、非十六进制及错误长度被拒绝；省略字段的旧响应仍接受。原有无修改、分页尾部和摘要身份检查继续通过。
- MCP 全量 50 项：49 通过、1 项因 Windows 文件符号链接权限跳过；10 项协议烟测通过。Web 类型检查和最终生产构建通过。独立服务包 Node 22/Web/MCP、认证 SSE、完整模型 URL、SDK 循环及 Chromium 宽窄问答流程通过，包括连续提问、后台标题、历史、来源往返、中断与保存重试。证据：`.local/rag-evidence-version-payload-20261011`、`.local/rag-evidence-version-package-check-20261011` 和 `.local/rag-evidence-version-tests-20261011.txt`；未生成或安装 NSIS 包。

本批未调用真实模型，版本保护由确定性测试证明，不用付费回答质量样本代替。没有发布、安装、访问真实资料或操作鸿蒙设备；各客户端复用后端的错误事件。

## 验证边界与维护

这是单个日块在一次请求内的版本绑定，不是整个资料库的全局事务快照；不同日期独立绑定各自第一次读取的版本。范围分页仍由原有 revision 保护整个所选范围。没有新增长任务恢复或跨重启执行。

首次测试布置时把日志根与索引目录嵌套，按既有安全规则被拒绝；修正为并列目录后通过。失败遗留临时目录 `%TEMP%\rag-version-ZLYA81` 只含一份合成测试日志。清理命令自动审批拒绝，返回信息未给出更细原因；本批保留该目录，未绕过拒绝继续删除。后续通过的查询测试自行释放服务并清理各自临时目录。
