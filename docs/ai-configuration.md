# AI 配置与模板

日志生成、重点标注和随记候选已接入，均需审阅后显式保存。`/api/capabilities` 需要认证，`aiConfiguration` 仅报告本地配置和模板检查结果；不会探测供应商、消耗费用或返回配置值，也不保证供应商当前可用。`features` 的 `supported` 另行表示功能是否实现。

实例 `.env` 中显式填写以下变量，保存后重启该实例：

```dotenv
CHAT_API_URL=https://your-provider.example/v1/chat/completions
CHAT_MODEL=your-model
CHAT_API_KEY=replace-with-your-key
```

地址是完整的 OpenAI 兼容聊天接口地址，不会自动追加路径。可显式使用 HTTP 代理；是否加密取决于管理员填写的地址。不得在地址中嵌入用户名、密码或片段。可选 `CHAT_LIGHT_MODEL` 指定轻量任务模型，空值使用 `CHAT_MODEL`。没有内置供应商、模型或个人环境变量回退。

问答可选 `RAG_DEEPSEEK_THINKING=disabled` 或 `low`，仅适用于 HTTPS 官方 `api.deepseek.com` 的 `deepseek-flash`、`deepseek-v4-pro`。留空沿用供应商默认行为；不会自动关闭思考或更换模型。`disabled` 发送 `thinking.type=disabled`，不发送无效的 `reasoning_effort=none`；`low` 发送 `thinking.type=enabled` 和 `reasoning_effort=low`。普通问答最终生成与 SDK 工具循环使用相同参数。此设置不改变轻量规划、材料压缩、会话标题或其他模块的 AI 调用；代理接口不凭模型名推断兼容性，显式配置不支持的组合时问答返回配置错误，不静默忽略。保存后重启实例生效，现有桌面模型设置窗口仍只管理地址、模型和密钥。参数依据：[DeepSeek 思考模式](https://api-docs.deepseek.com/guides/thinking_mode/)。

Agent 不按供应商地址或模型名启用。`RAG_AGENT_TOOL_CALLING_VERIFIED=true` 仍需显式确认；`RAG_AGENT_ENABLED` 未设置或为 true 时允许按需运行，false 关闭，其他值不启用。新实例总开关为 true、能力确认为 false；已有实例不自动改写。材料充分时首个 SDK 调用可直接答复，实际补查或超限材料处理才计为进入 Agent；完整范围已读且材料容纳得下、以及字面查找继续直接生成。Jev 不自动启用，DeepSeek 只是验收样本。

长范围总结的“仍待解决”窄核对由 `RAG_STATUS_VERIFICATION_ENABLED=true` 单独启用，不从 Agent 开关、供应商或模型名推断。只有完整读取至少 14 个日志日块且回答确实产生该小节时才增加一次结构化核对；模型不兼容结构化输出时保留原回答并提示核对未完成。

如已核实模型上下文窗口，可设置 `RAG_CONTEXT_WINDOW_TOKENS` 为大于 `98304` 的整数。未设置时按 30,000 字符的保守兼容上限处理，不按供应商名称猜测容量。该值随回答模型变化必须重新确认。

能力接口的 `features.rag.configured` 使用与问答请求相同的思考模式校验；可选 `features.rag.issues` 返回固定诊断文字，不返回配置值。网页在既有“检查说明”中显示错误并禁用发送，已有会话仍可查看。其他 AI 功能的就绪状态不因问答专用设置错误而关闭；旧客户端不识别 issues 时仍可使用 configured，旧服务器缺少 issues 时网页沿用通用提示。检查不会探测模型或消耗费用。

桌面端保存不同的模型名称或完整接口地址时，已有的工具调用确认和范围末状态核对会关闭，上下文窗口声明会清空，避免把旧模型能力沿用到新目标。`RAG_AGENT_ENABLED` 保留；目标相同的重复保存不撤销确认。新目标未重新确认时正常使用普通 RAG，不自动探测或产生验证费用。服务器管理员手动修改环境文件时也应同步更新这三项能力设置。

初始化会将仓库 `prompts` 中三个通用模板复制到实例的 `data/prompts`：`generation.md`、`highlighting.md`、`extraction.md`。模板强调材料依据、结果预览和用户决定，不规定个人领域、文风、括号或中英文空格习惯。每次请求重新读取模板，修改后无需重启；文件须为非空 UTF-8 普通文件，最大 64 KiB，路径不能包含链接。

升级已有实例时，停止该实例后重新运行初始化即可补充缺失模板；已有密码、环境文件和自定义模板保留。旧环境文件中的 AI 变量需自行添加。缺少或无效模板会给出具体模板名和原因，不读取其他实例或个人 Skill。

默认重点标注选择少量值得回顾的完整语义，保留否定、条件和状态限定，也允许没有合适的标注。模型只能选择原文范围，不能改写正文；结果仍须审阅和显式应用。

## 内置默认模板升级

本轮源码新增自动升级：Windows 本地服务、服务器 Web 启动和实例初始化共用 `ops/instance.mjs`，取得实例锁后、接收请求前执行。只更新与已发布 rc.5 内置 `highlighting.md` 或 `extraction.md` 逐字节一致的文件，每个模板识别 Git 的 LF 与 Windows 旧包的 CRLF 两份摘要；不按关键词推断，也不转换用户文件换行。rc.5 已发布程序本身不具备这项新增逻辑，需要使用后续构建。

自定义、未知版本或无法安全读取的模板保留。`generation.md`、个人生成方案及默认选择不自动修改。新实例直接使用当前内置模板。

更新前把原文件保存在 `data/prompts/.default-upgrades/<模板名>-<旧摘要>.md`，确认备份一致后原子替换。重复启动不重复备份或改写。维护结果位于同目录 `status.json`（标注）或 `extraction-status.json`（提取），记录模板名、更新摘要或跳过／失败原因，不记录正文或凭据；当前文件已经是新版时保留上次记录。若连记录也无法写入，仅在服务日志输出固定维护提示。更新失败保留旧模板，基础记录服务继续启动。

完整备份包含模板及这份升级备份。人工处理前正常停止实例，再按对应维护记录指向的模板检查读写权限和文件类型；不要删除实例运行锁来绕过检查。修改过的模板如需使用新版规则，由维护者自行对照合并，不自动覆盖。

默认提取围绕同一问题保留完整上下文，将过程、结论与限制一起审阅，不单独提取材料名称、临时计划或重复推断。

## 日志生成方案

日志 AI 面板可选择生成方案，旁边的管理入口支持新增个人方案、复制内置方案、编辑名称和提示词、删除及设为默认。日常学习整理、概念与例题、实践与排错是只读预设；修改前先复制为个人方案。提示词描述组织和表达偏好，不能代替服务端的单日日志结构校验，也不会自动保存生成结果。

“现有默认方案”继续读取实例的 `data/prompts/generation.md`。升级不改该文件；旧客户端省略方案标识仍使用它，即使新界面已设置其他默认方案。个人方案与默认选择保存在实例 `data/prompts/generation-presets.json`，写入有版本保护和写前备份，整实例归档包含该文件。发生其他页面已修改的冲突时，编辑内容保留，由用户刷新并核对后重试。

导入教材、文章和代码不等于用户已经学习、掌握或亲自完成实验。默认预设保留材料依据，个人方案也应避免虚构学习经历。标注和随记提取仍使用原有独立模板，不受日志方案选择影响。
